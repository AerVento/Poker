# 持久账户现金桌客户端验收

## 验收构建

- Windows 客户端：`Build/Acceptance/Client/Poker.exe`
- Linux Dedicated Server：`Build/Acceptance/Server/Poker.x86_64`
- 服务端账户数据库位于 Unity 的 `Application.persistentDataPath/PokerAccounts.db`。

验收环境只应用于开发阶段内网。当前传输没有 TLS/WSS，不应把测试密码用于公网或其他系统。

## 基本流程

1. 启动一台服务器和至少三个客户端 A、B、C。
2. 标题页应只显示“开始游戏”入口；点击后进入独立登录界面。分别注册三个大小写明确的用户名；确认每个新账户注册后直接登录并显示 `$10,000`，错误密码不能登录，重复注册同名账户会被拒绝。
3. A 创建房间，设置盲注和最大人数；确认界面中不再有“初始筹码”设置。
4. B 加入并准备，A 开始首手。确认房间筹码来自各自账户余额。
5. 首手进行期间让 C 加入：C 应显示“等待下一手”，不能看到任何玩家底牌，也不能操作。
6. 结束首手：三个客户端应看到 10 秒倒计时；下一手开始后 C 应立即获得两张底牌并正常参与，不额外补交大盲。
7. 在倒计时中让一名玩家离开；服务器应在开局前重新统计人数。少于两名合格玩家时返回房间主界面，之后必须由新房主手动开始。

## 断线与顶号

1. 轮到 B 且无需跟注时断开 B：服务端应自动过牌；需要跟注时应自动弃牌。
2. 本手结束前重新登录 B：应回到原座位，只参与之后尚未发生的操作。
3. B 已 all-in 后断线：B 不应被弃牌，仍保留有资格竞争的主池或边池。
4. B 尚在线时，从另一客户端登录 B：新连接应替换旧连接；旧连接随后发送的操作或断线回调不得改变新连接状态。
5. 本手结束时仍断线的玩家应转为旁观并释放座位；下次登录时若房间仍存在，应询问返回或离开。

## 账户与房间生命周期

1. 登录成功后关闭并重新打开客户端，再次点击“开始游戏”；客户端应使用浏览器或本机保存的会话令牌自动登录，不再要求输入密码。
2. 自动登录成功后令牌应完成轮换，旧令牌不能再次使用；保存状态过期或无效时应留在登录界面并要求重新输入密码。
3. 从大厅打开设置页，确认只读显示当前用户名，旧昵称输入框已经移除；点击“登出”后应回到标题页并清除本地登录状态，下次点击“开始游戏”必须重新输入密码。
4. 房主离开后房间继续存在，并把房主转移给剩余成员。
5. 最后一名成员离开后房间立即解散；旧账户再次登录时不应询问返回已解散房间。
6. 在房间 A 获胜后正常离开，再加入房间 B；余额应直接沿用，不存在兑回或重新买入步骤。
7. 余额少于一个大盲时应提示继续旁观或离开，且不能参加下一手。
8. 重启服务器后重新登录；账户、密码、持久会话和筹码应来自 SQLite，而不是客户端自行认定。由于房间状态目前不跨进程保存，重启后原 `LastRoomId` 应作为失效房间关联被清除。

## 已自动验证的同范围场景

- 一台独立服务器加三个独立客户端进程完成注册、建房、首手中途加入、两手牌、10 秒续局和离房。
- 第三个客户端首手收到 `WaitingForNextHand` 且没有底牌，第二手收到 `Playing` 且有两张底牌。
- 同一测试数据库由第二个服务器进程重新打开后，对账仍一致。
- 数据库下注失败、结算暂时失败后重试、重复扣款/结算请求、活动手牌崩溃退款均由 EditMode 测试覆盖。
- 账户余额、账本净额、活动手牌投入以及结算后主池、边池和退款均执行守恒检查。
