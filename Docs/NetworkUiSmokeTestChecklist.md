# 新版本联网 UI 冒烟测试清单

本轮执行记录见 [2026-09-11 测试报告](NetworkUiSmokeTestReport-2026-09-11.md)。清单勾选不代表未经验证的项目已通过。

## 1. 目的与范围

本清单用于验证当前大批量改动后的第一轮可玩性，不替代完整规则回归、平台构建或压力测试。本轮重点确认：

- 一个服务端与至少两个客户端能够通过正式 UI 完成联网主流程。
- 服务端状态能够正确同步到各客户端，界面不会显示过期或互相矛盾的数据。
- 本次新增或大幅调整的界面在常用分辨率下清晰、美观、可操作。
- 页面切换、弹窗和断线处理不会造成界面叠层、点击穿透或无法继续操作。

视觉与交互验收以 [UIConvention.md](UIConvention.md) 为准。测试只记录实际观察到的结果；离线样例、EditMode 测试或历史报告不能代替本轮真实联网结论。

## 3. 开始前检查

- [ ] 保存当前工作区状态，确认测试过程不会覆盖现有修改。
- [ ] Unity 完成脚本编译，Console 没有新增 error。
- [ ] `Game.unity`、Manager prefab 和本轮涉及的 UI prefab 没有 Missing Script 或 Missing Reference。
- [ ] `UIManager` 中所有面板注册项非空且没有重复类型。
- [ ] 服务端与客户端使用相同协议和资源版本。
- [ ] 准备两个可重复使用的测试账户，记录初始美金、筹码和物品状态。

任一编译错误、关键引用断裂或协议版本不一致均视为阻断问题，应先停止联网 UI 测试。

## 4. 最小联网主流程（P0）

### 4.1 标题、登录与大厅

- [ ] 两个客户端均能从标题页打开登录页，不会在认证前进入房间列表。
- [ ] 登录和注册页签切换正确，输入框、确认密码、错误提示及按钮没有重叠。
- [ ] 错误密码不会登录；失败后输入内容和操作能力合理保留。
- [ ] 登录请求期间不能重复提交，成功后只进入一次大厅。
- [ ] 大厅显示正确的用户名、美金和筹码，两个账户不会串号。
- [ ] 房间、排行榜、成就、每日任务、商城、收藏、设置和兑换入口完整、易于辨认。
- [ ] 大厅图标、文字、对齐、间距、圆角和配色保持统一。

### 4.2 建房、入房与等待界面

- [ ] 客户端 A 能创建房间，客户端 B 能从房间列表看到并加入。
- [ ] 房间名、盲注、人数、房主和玩家列表在两端一致。
- [ ] 玩家加入、离开、准备及取消准备后，两端及时刷新。
- [ ] 参战／旁观开关状态明确，切换结果以服务端回执为准。
- [ ] 座位或筹码条件不满足时，按钮状态和简短原因正确。
- [ ] 只有满足开始条件时房主才能开始游戏。
- [ ] 返回大厅和离开房间不会产生重复面板或错误返回目标。

### 4.3 牌桌

- [ ] 至少完成一手牌，覆盖发牌、过牌／跟注、加注或全下、弃牌和结算。
- [ ] 公共牌、自己的底牌、奖池、当前下注、玩家筹码及行动顺序正确。
- [ ] 其他玩家底牌和仅服务端可见的信息没有泄漏。
- [ ] 当前行动玩家、倒计时和行动结果显示清楚且不互相覆盖。
- [ ] 过牌、跟注、加注、全下和弃牌按钮仅在合法时可用。
- [ ] 加注输入框与执行按钮的视觉和点击区域彼此独立。
- [ ] 弃牌玩家持续显示“弃牌”；旁观玩家显示眼睛标记及半透明状态。
- [ ] 打开设置、任务、兑换或上手回看时，牌桌快捷键和鼠标点击不会穿透。
- [ ] 关闭覆盖页面后，牌桌仍显示最新服务端状态。

### 4.4 单手结算与下一手

- [ ] 两端看到的赢家、从奖池领取的金额、牌型、公共牌和底牌信息一致。
- [ ] 未摊牌玩家不显示伪造或不应公开的牌型。
- [ ] 多玩家列表间距一致；末行人数不足时排列自然。
- [ ] 长用户名、大额数字和滚动到底部不会遮挡或裁切关键信息。
- [ ] 弹窗可关闭且不会点击穿透；关闭后可以正常进入下一手流程。
- [ ] 下一手开始后旧结算回调不会重新打开或更新已失效界面。

### 4.5 离房与断线

- [ ] 一名玩家正常离房后，另一端房间或牌桌状态及时更新。
- [ ] 房间人数不足时，相关玩家进入设计规定的等待或旁观状态。
- [ ] 客户端断线后显示简短、明确且可操作的提示。
- [ ] 重新登录、离开房间和返回标题页按钮执行各自语义，不复用旧回调。
- [ ] 断线后牌桌不可见且不在活动导航层级中。

## 5. 联网功能页面（P1）

### 5.1 钱包与筹码兑换

- [ ] 大厅和牌桌入口均打开同一套有效账户数据。
- [ ] 美金与筹码使用不同的统一图标，兑换方向和金额清楚。
- [ ] 非法金额、余额不足及重复提交不会改变余额。
- [ ] 成功兑换后，兑换页、大厅和牌桌余额同步刷新。
- [ ] 兑换不会自动改变参战／旁观或准备状态。

### 5.2 商城与收藏

- [ ] 服务器商城数据加载成功，加载、空状态和失败状态不混淆。
- [ ] 物品、名片和牌面页签切换后不会残留上一页签内容。
- [ ] 名称、介绍、价格、图标和购买按钮完整且关联清楚。
- [ ] 购买成功后余额、库存和按钮状态同步更新。
- [ ] 余额不足、已拥有或不可购买时有正确禁用状态或简短反馈。
- [ ] 收藏中的装备、使用和契约还款以服务端结果为准。
- [ ] “宝石宫廷”牌面缩略图、详情和实际牌桌牌面一致。

### 5.3 成就与每日任务

- [ ] 成就和任务数据来自当前登录账户，不会显示上一账户缓存。
- [ ] 名称、描述、进度、奖励、领取状态和图标完整。
- [ ] 隐藏成就不会提前泄露不应展示的信息。
- [ ] 领取成功后进度、状态和美金立即同步；重复操作不重复发奖。
- [ ] 每日任务显示实际重置规则和时间。
- [ ] 牌局中允许／禁止领取的状态符合当前参与、弃牌和结算阶段规则。
- [ ] 长列表滚动、返回及重新打开后状态正确。

### 5.4 设置与导航

- [ ] 标题、大厅和牌桌均能打开对应设置界面。
- [ ] 返回按钮回到实际来源页面，不依据登录状态猜测目的地。
- [ ] 标题页进入设置时隐藏登出；已登录时用户名只读且登出可用。
- [ ] 音量、快捷键、开关和恢复默认具有清晰状态反馈。
- [ ] Tab／Shift+Tab 焦点顺序合理；输入和改键时牌局快捷键不触发。
- [ ] 重复打开、关闭或快速点击不会叠加多个单例面板。

## 6. 视觉与交互检查

每个重点页面至少检查标题、登录、大厅、房间、牌桌、结算、兑换和设置。

- [ ] 墨绿、香槟金和暖白主题统一，没有默认 Unity 白灰控件或不成套图标。
- [ ] 面板、弹窗、卡片、输入框和按钮使用一致的圆角与边框体系。
- [ ] 标题、正文、次要信息和主操作层级清楚。
- [ ] 对齐、间距、内边距和按钮尺寸统一，主要操作容易找到。
- [ ] 返回、关闭、删除、设置、商城和收藏使用约定图标及正确语义。
- [ ] 正常、悬停／焦点、按下、选中和禁用状态均可辨认。
- [ ] 控件完整区域可点击，相邻热区不重叠，装饰元素不阻挡 Raycast。
- [ ] 长用户名、最大金额、空列表、满列表、加载和错误状态不破版。
- [ ] 玩家文案简短且有实际用途，不展示内部实现或调试信息。
- [ ] Console 没有因打开、关闭、缩放或断线产生的新 error。

## 7. 分辨率与网页等比显示

游戏内部保持横屏设计布局，不使用按方向重排的运行时响应式组件。WebTemplate 占满浏览器可用区域，按构建宽高比居中等比显示游戏；横屏空间允许时 FitHeight、竖屏 FitWidth，比例不匹配时允许留边，不裁切。

- [ ] 1920×1080、1366×768 和一个 16:10 分辨率下主操作完整可见。
- [ ] 浏览器窗口改变大小时保持设计宽高比，不拉伸、不裁切游戏内容。
- [ ] 390×844 竖屏访问时等比缩小整个游戏，不重排内部页面。
- [ ] 横竖屏切换后恢复相同游戏布局，不累计缩放或改变页面状态。
- [ ] 软键盘出现和隐藏后网页容器正确更新，输入仍可操作。
- [ ] 页面无滚动条；安全区内画布居中，加载条和错误提示仍正确定位。

## 8. 通过标准

本轮“最小联网 UI 冒烟测试”通过需要同时满足：

- P0 主流程全部通过，没有阻断登录、建房、入房、开局、操作、结算和离房的问题。
- 两个客户端的关键状态与服务端一致，没有隐私泄漏、串号或重复提交。
- 1920×1080 下所有 P0 页面达到可操作且无明显视觉缺陷。
- Console 没有新增 error，关键 prefab 和场景没有 Missing Script / Reference。
- 所有未执行的 P1、分辨率或平台项目均明确记录，不能默认为通过。

P0 通过后，再安排三客户端、断线恢复、旁观、复杂边池、Linux Server、WebGL 浏览器及移动真机回归。
