# 账户筹码、持续牌桌与断线重连改造计划

## 1. 改造目标

将当前“房间创建后固定玩家、每位玩家领取房间初始筹码、持续到只剩一人”的封闭牌局，改造成支持持久账户和动态玩家的无限注德州扑克牌桌：

- 使用用户名和密码注册、登录账户。
- 账户筹码必须写入数据库，并在服务器重启后保留。
- 账户筹码就是玩家能够下注的全部筹码，不存在账户钱包与桌上筹码之间的买入、兑回步骤。
- 玩家进入牌桌后，当前账户筹码全部可用于下注；一手开始后不能在牌局内领取新筹码。
- 同一账户任何时刻只能位于一个房间、参与一张牌桌。
- 玩家可以在牌局运行期间进入房间，从下一手立即参与。
- 玩家断线期间本手继续自动操作；本手结束仍未连接则转为旁观。
- 新连接成功登录同一账户时，总是替代旧连接并恢复该账户状态。
- 房间持续存在并转移房主；满足条件时自动开始后续手牌。

本计划默认筹码是不可兑换真实货币的游戏内整数筹码。充值、提现、真实货币兑换以及筹码耗尽后的领取机制不在本次实现范围内。

## 2. 已确认的产品规则

### 2.1 账户与筹码

1. 资金主键是不可变的 `AccountId`；用户名用于登录和显示，但不直接作为内部关联主键。
2. 新账户初始筹码固定存储为整数 `10,000`，由服务器配置提供，不能由客户端指定；UI 显示为 `$10,000`。
3. 账户当前筹码就是可参与牌局的筹码，不设置单独的买入额、桌上钱包、最小买入或最大买入。
4. 一手开始时确定该手可使用的筹码上限。一手进行中没有领取新筹码的途径；在房间外领取的筹码只能用于之后加入的手牌。
5. 玩家必须至少拥有一个大盲的筹码，才能加入或重新加入牌局。
6. 玩家手牌结算后不足一个大盲时不能参加下一手：
   - 客户端提示筹码不足；
   - 玩家可选择留在房间旁观；
   - 玩家也可选择离开房间；
   - 筹码耗尽后的领取机制以后另行实现。
7. 用户名区分大小写且注册后不可修改；第一版账户功能只实现注册和登录。

### 2.2 房间与手牌

1. 房间设置盲注和最大座位数；不再设置每位玩家的 `InitialChips`。
2. 新玩家在当前手牌中进入房间时只等待和旁观，不参与当前手牌，也不能看到私有牌局状态。
3. 新玩家只要在下一手开始时已连接、已入座且筹码不少于一个大盲，就立即参与下一手；不要求等待大盲位置，也不额外补交大盲。
4. 房主离开时将房主身份转移给仍在房间的玩家，房间不会仅因原房主离开而解散。
5. 一手结束后，如果至少有两名可参赛玩家，则进入 10 秒倒计时，然后自动开始下一手。
6. 10 秒倒计时内玩家可以离开；开局时重新检查人数、连接状态和筹码资格。
7. 如果可参赛玩家不足两人，则停止自动开局并返回房间主界面；之后即使恢复到两人，也必须由房主再次手动开始。
8. 房间最后一名已连接成员离开后，房间立即解散。

### 2.3 断线与顶号登录

1. 不使用固定秒数判定断线玩家离桌。
2. 玩家在一手中断线后，该手剩余时间内继续采用自动操作：可以过牌时自动过牌，否则自动弃牌。
3. 已经 all-in 的断线玩家仍参与其有资格竞争的奖池。
4. 当前手牌结束前重新登录成功，可以恢复到原座位并继续之后尚未发生的操作；已经自动完成的操作不回滚。
5. 当前手牌结束时仍未连接，玩家转为旁观，不参与下一手，原参赛座位可以释放。
6. 玩家之后重新登录时，根据数据库记录的 `LastRoomId` 检查上次房间：
   - 房间仍存在时，询问玩家是否重新加入；重新加入按中途加入处理；
   - 房间已解散时，不显示重连询问，直接进入大厅；
   - 玩家选择不重新加入时，视为离开该房间并清除 `LastRoomId`。
7. 同一账户发生新登录时，新连接总是替代旧连接：
   - 服务端先原子更新账户与会话的连接绑定；
   - 再断开旧连接；
   - 旧连接迟到的断线回调不得覆盖新连接状态。

## 3. 必须保持的系统不变量

以下约束全部由服务端强制执行，不能信任客户端提交的用户名、账户 ID、座位号、筹码数或玩家下标。

### 3.1 全局筹码守恒

系统任意时刻应满足：

```text
所有账户尚可下注的筹码
+ 所有进行中手牌已经投入的筹码
+ 所有主池、边池和待退回筹码
= 可追踪的系统筹码总额
```

- 玩家下注时，筹码从该账户的可用筹码转入当前手牌投入。
- 奖池结算后，筹码直接增加到获胜账户。
- 未被跟注的筹码退回原账户。
- 网络重试、顶号登录和迟到消息不能重复下注或重复结算。
- 领取筹码功能以后实现时，也必须通过服务端账本增加筹码，不能直接覆盖余额。

### 3.2 一手内的筹码上限

- 每手开始时记录每位参与者的 `HandStartingChips`。
- 一手中的累计有效投入不能超过该玩家本手开始时拥有的筹码。
- 本手赢得的奖池在结算后才成为下一手可用筹码。
- 玩家离开房间也不能撤回已经投入当前手牌的筹码。

### 3.3 单账号单房间

一个账户只能处于以下一种业务位置：

- 大厅或离线，未关联房间；
- 在某房间旁观或等待入局；
- 在某房间参与当前手牌；
- 在某房间断线，但当前手牌尚未结束；
- 当前手结束后记录着可选择返回的上次房间。

新登录可以替代同一账户的旧连接，但不能使该账户同时出现在两个房间。加入新房间前必须明确离开或清除仍存在的上次房间关联。

### 3.4 身份与密码安全

- 密码绝不以明文写入数据库或日志。
- 数据库存储带随机盐、带成本参数的密码哈希。
- 登录成功后使用服务端会话身份处理请求，不继续信任消息中自报的用户名。
- 修改筹码、加入房间、下注、离桌和重连都必须验证当前连接拥有对应账户会话。
- 旧会话被替代后，其所有后续消息都必须被拒绝。
- 第一版仍沿用当前未启用 TLS/WSS 的传输配置，因此只能视为开发阶段认证；公网密码传输安全将在下一份计划中处理，不能把当前版本声明为可安全公网发布。

## 4. 目标领域模型

### 4.1 PlayerAccount

- `AccountId`：不可变唯一标识。
- `UserName`：唯一登录名。
- `DisplayName`：玩家显示名；第一版可以与用户名相同。
- `PasswordHash` / `PasswordSalt` / `PasswordParameters`。
- `Chips`：当前尚可下注的整数筹码。
- `LastRoomId`：可空，仅用于下次登录时询问是否返回。
- `Version`：用于并发更新或乐观锁。
- `CreatedAt` / `LastUpdatedAt`。

### 4.2 AccountSession

- `SessionId`：每次成功登录生成的新版本会话 ID。
- `AccountId`。
- `ConnectionId` 或当前 Mirror 连接引用。
- `RoomId` / `SeatId`。
- `State`：`Lobby`、`Spectating`、`WaitingForHand`、`Playing`、`DisconnectedInHand`。

`SessionId` 用于解决顶号竞态：旧连接的消息和断线回调只有在其会话仍为当前版本时才允许改变账户状态。

### 4.3 ChipLedger

所有会改变系统筹码总量或账户归属的动作都生成不可变账本记录：

- `TransactionId`。
- `RequestId`：用于幂等处理网络重试。
- `AccountId`。
- `RoomId` / `HandId`。
- `Type`：注册初始发放、下注投入、未跟注退回、奖池收入、未来领取、管理修正等。
- `Amount`。
- `BalanceBefore` / `BalanceAfter`。
- `CreatedAt`。

具体实现可以对一手内高频下注采用事务化手牌状态与批量账本，但服务崩溃恢复后仍必须能够证明筹码守恒，不能只在内存中保存关键余额。

### 4.4 TableSeat

- `SeatId`：固定座位编号，不因玩家离开而使其他座位整体移动。
- `AccountId` / `DisplayName`：空座时为空。
- `State`：`Empty`、`WaitingForHand`、`Playing`、`Spectating`、`DisconnectedInHand`、`LeavingAfterHand`。
- 当前会话引用。

`RoomInfo.Players`、`ReadyStatus` 与 `ServerGameInfo.Players` 当前依赖平行列表和可变下标，后续应改为固定 `SeatId`。手牌内部可建立本手参与者快照，但不能假设房间玩家集合在整场房间生命周期内固定不变。

### 4.5 PokerRoom

- `RoomId`。
- `OwnerAccountId`。
- `SmallBlind` / `BigBlind`。
- `MaxSeats`。
- 固定座位集合与旁观者集合。
- `State`：`Lobby`、`HandInProgress`、`InterHandCountdown`。
- 下一手开始时间；自动开局倒计时固定为 10 秒。

### 4.6 HandParticipant

当前手牌开始时，从合格座位生成不可变的参与者快照：

- `HandId` / `AccountId` / `SeatId`。
- `HandStartingChips`。
- 当前剩余筹码、街道投入、本手总投入。
- fold、all-in、断线和操作状态。
- 仅服务端可见的底牌。

中途进入房间、转为旁观或旧连接断开，都不能改变已经生成的本手参与者集合。

## 5. 关键流程

### 5.1 注册与登录

1. 注册时服务端验证用户名唯一性并安全哈希密码。
2. 在同一数据库事务中创建账户、发放初始 `10,000` 筹码并写入账本。
3. 登录成功后生成新的 `SessionId`，原子替代该账户旧会话。
4. 服务端断开旧连接；旧连接迟到消息因会话版本不匹配而失效。
5. 读取 `LastRoomId`：房间存在则询问是否返回，不存在则清除该字段并进入大厅。

### 5.2 加入房间和中途入局

1. 服务端确认账户没有关联其他房间，并且筹码不少于当前房间一个大盲。
2. 玩家进入空座；若当前手牌正在进行，则进入 `WaitingForHand` 并旁观。
3. 下一手开始时重新验证连接、座位和筹码资格。
4. 验证通过后立即加入该手，不要求补交额外大盲。

### 5.3 一手结束与自动续局

1. 完成主池、边池、未跟注退回与账户筹码更新。
2. 筹码少于一个大盲的玩家转为旁观并收到筹码不足提示。
3. 当前仍断线的玩家转为旁观并释放参赛座位。
4. 重新统计已连接、已入座且筹码不少于一个大盲的玩家。
5. 至少两人时启动 10 秒倒计时；倒计时 UI 允许玩家离开。
6. 倒计时结束时再次校验人数：
   - 仍有至少两人则自动开始下一手；
   - 不足两人则取消开局，返回房间主界面等待。
7. 回到房间主界面后不再自动倒计时，必须由房主手动开始新的连续牌局。

### 5.4 正常离开

- 未参与当前手牌时立即离开并释放座位，清除 `LastRoomId`。
- 正在参与当前手牌时标记 `LeavingAfterHand`；后续需要行动时自动过牌，否则自动弃牌。
- 已 all-in 时保留奖池资格。
- 当前手牌结算后释放座位并清除房间关联，不存在兑回筹码步骤。
- 最后一名已连接成员离开时立即删除房间；以后登录账户中残留的 `LastRoomId` 按无效房间处理。

### 5.5 断线与恢复

1. 当前手牌中断线：保留本手参与者和座位，状态改为 `DisconnectedInHand`。
2. 该手需要行动时自动过牌，否则自动弃牌。
3. 本手结束前成功登录：新连接替代旧连接并恢复原座位，继续尚未发生的操作。
4. 本手结束仍未登录：转为旁观、释放参赛座位，并在账户中保留 `LastRoomId`。
5. 下次登录：若房间仍存在，询问返回或离开；选择返回时按中途加入处理。

### 阶段 2：账户筹码直接驱动牌局

- [x] 从服务端房间配置和开局逻辑移除 `InitialChips`；旧协议字段暂留兼容，服务端忽略。

- [x] 保证一手内不能获得或使用额外筹码，并阻止同一账户同时进入第二手牌。
- [x] 在服务端处理不足一个大盲和零筹码的参赛资格；用户提示留到阶段 5 UI。
- [x] 增加数据库失败、重复结算和服务恢复测试。

阶段 2 决定将账户余额统一为 `uint`，账本变动量保留为有符号 `long`。SQLite 手牌事务原子记录盲注和每次投入，以请求 ID 保证幂等；正常结束原子派奖，服务器重启或牌局异常关闭则按已投入金额退款。为保证任一赢家都不会溢出，开手时要求所有参赛账户余额总和不超过 `uint.MaxValue`。

验收：玩家在 A 房间赢得的筹码无需兑回即可在离开后进入 B 房间使用；所有筹码变化可追踪且守恒。

- [x] 实现房主转移，取消“剩余一人即 GameOver 并删除房间”。
- [x] 实现至少两人时的 10 秒自动续局倒计时。
- [x] 人数不足时返回房间主界面，并要求房主手动重新开始。
- [x] 最后一名成员离开时立即解散房间。
- [x] 适配按钮、盲注、空座、heads-up 转换和按座位裁剪的网络状态；新状态的 UI 展示留到阶段 5。

阶段 3 使用 `RoomSeatInfo.SeatIndex` 作为牌桌生命周期内的稳定座位标识。牌局中加入者先处于 `WaitingForNextHand`，没有底牌和操作权；当前手结束后重新读取账户余额，拥有至少一个大盲且在线的玩家参加下一手。牌局中离开会立即失去后续操作权，但其座位要到本手结算后才释放，避免座位复用污染奖池和底牌。连续牌局结算后等待 10 秒并再次校验人数；不足两人时保留房间、重置准备状态并回到手动开始流程。

验收：玩家集合变化不会破坏发牌、按钮、下注顺序或奖池；10 秒内离开会阻止不满足人数的下一手启动。

### 阶段 4：断线、旁观与状态恢复

- [x] 客户端断线时显示重新登录/离开选择。
- [x] 当前手中实现 `DisconnectedInHand` 自动操作和恢复。
- [x] 手牌结束后断线玩家转旁观并释放座位。
- [x] 登录时检查 `LastRoomId` 和房间存在性。
- [x] 返回房间时按中途加入处理，不返回时清除关联。
- [x] 处理顶号、网络抖动、旧连接迟到回调和房间已解散。

阶段 4 将房间成员拆分为固定参赛座位与不占座的 `Spectators`：断线玩家在当前手仍保留 `DisconnectedInHand` 座位并自动过牌/弃牌；本手结束仍离线或筹码不足者转入旁观集合并立即释放座位。重新认证时，服务端先校验数据库中的 `LastRoomId` 是否仍对应一个存在的房间，再由客户端选择返回或离开；返回者按中途加入规则占用空座，不满足一个大盲或没有空座时仅旁观。顶号登录如果原会话仍在线且房间关联有效，则直接把当前状态交给新连接，旧连接的迟到断线回调仍不能改变新会话。

断线发生后无法在离线连接上立即向服务器提交“离开”，因此客户端会记录该选择，并在下一次成功认证后由已认证会话清除房间成员和 `LastRoomId`。登录界面现已在 `TitlePanel.prefab` 中补齐用户名、密码、注册按钮和状态引用；断线与房间恢复选择复用现有 `MsgBox`。UI prefab 约定记录在 [UIConvention.md](./UIConvention.md)。

验收：本手内恢复可以继续操作；本手后恢复只能从下一手加入；拒绝返回不会留下座位或跨房间占用。

## 7. 自动化测试矩阵

- 注册账户得到一次且仅一次的 `10,000` 初始筹码。
- 服务器重启后账户密码、筹码和 `LastRoomId` 保留。
- 同一账户新登录替代旧连接；旧连接消息与迟到断线回调无效。
- 同一账户不能同时关联两个房间。
- 玩家筹码等于大盲时可以加入；少于大盲时只能旁观或离开。
- 当前手牌期间加入，只从下一手获得底牌。
- 新玩家下一手立即参与，不额外补交大盲。
- 玩家在按钮、小盲、大盲位置前后加入或离开。
- 三人桌变两人桌、两人桌增加到三人桌时的按钮和盲注。
- 断线时可过牌、需要跟注、已经 all-in、已经弃牌。
- 当前手结束前恢复与当前手结束后恢复的不同结果。
- 断线玩家在手牌结束后转旁观并释放座位。
- 10 秒倒计时期间有人离开，开局前人数会重新校验。
- 不足两人时回到房间主界面，房间不会因原房主离开而错误删除。
- 客户端重放请求或伪造其他账户、座位、玩家下标。
- 下注、主池、边池、退款和结算后的全局筹码守恒。

## 9. 明确不在本次范围内

- 一个账户同时进入多个房间或同时进行多桌游戏。
- 单独的桌上钱包、买入、补充买入和离桌兑回。
- 筹码耗尽后的领取机制。
- 修改密码、找回密码和修改用户名。
- TLS/WSS、公网证书与安全传输部署；该项进入下一份计划。
- 真实货币充值、提现和兑换。
- 玩家之间转账或赠送筹码。
- 客户端决定账户筹码、下注或结算结果。
- 允许新玩家加入正在进行的当前手牌。

## 10. 完成定义

- 账户、密码哈希和筹码在数据库中持久保存。
- 所有筹码变化都有服务端依据并满足全局守恒。
- 同一账户无法同时进入两个房间，新登录能安全替代旧连接。
- 玩家无需买入或兑回即可跨房间使用账户筹码。
- 中途加入只影响下一手，不改变当前手牌参与者和奖池。
- 断线玩家本手可恢复，本手结束后转旁观并按中途加入恢复。
- 房主转移、人数不足暂停和 10 秒自动续局符合已确认规则。
- 最后一名成员离开会立即解散房间；暂停后的牌局只能由房主手动重新开始。
