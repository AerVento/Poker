# Lua 成就系统设计方案

> 状态：提案，尚未实施。当前成就仍由 C# 类实现，见 [成就](../Systems/Achievements.md)。

## 1. 目的

当前每个具体成就由 C# 类型实现。新增或调整成就需要修改代码并重新发布服务器，无法满足运营期间快速增加、修改或删除成就的需求。

本方案将具体成就的定义和判定迁移到 Lua。Lua 负责描述成就、订阅业务事件并给出判定结果；C# 继续负责权威事件、持久化事务、奖励发放、网络同步和客户端展示。服务器可以在不重新构建程序的情况下重新加载 Lua 成就。

本方案只设计成就 Lua 化及其网络目录同步。牌面、物品、名片、成就图标等配置和资源的 AssetBundle 打包、下载、校验及切换属于后续独立方案，本文只预留衔接边界。

## 2. 已确认的产品决策

- Lua 成就文件不设置人工维护的版本号，也不为单个脚本建立版本迁移体系。
- Lua 只在权威服务器执行，客户端不下载或执行成就 Lua。
- 解锁通知携带该次展示所需的完整成就信息，不能依赖客户端已经缓存对应 ID。
- Lua 只提供成就定义、判定结果、进度建议和奖励信息；真正的完成、存档、领奖和资产变更全部由 C# 执行。
- Lua 由项目自身部署，不按不可信第三方代码设计复杂安全体系，只保留防止配置和开发失误所需的精简校验。
- 成就图标只能引用客户端当前能够加载的资源。图标不存在时使用默认图标，不影响成就解锁、展示和领奖。
- 删除 Lua 定义就表示删除成就：不再展示、不再判定，也禁止继续领取该成就的未领奖励。
- 新增成就只处理其加载后消费的事件，不回溯已经消费的历史事件。

## 3. 范围与非目标

### 3.1 本方案包含

- Lua 成就文件的组织方式和定义格式。
- C# 向 Lua 投影业务事件的稳定接口。
- Lua 判定结果和 C# 权威执行之间的边界。
- Lua 目录的加载、重载和原子切换。
- 成就展示目录与玩家状态的网络协议。
- 客户端目录缓存、解锁通知、隐藏成就和删除行为。
- 从现有 C# 成就迁移到 Lua 的步骤与验证要求。

### 3.2 本方案不包含

- 客户端 AssetBundle 的构建、下载、校验、缓存和回滚。
- 新图标在旧客户端上的动态下载。
- 牌面、物品、名片等其他配置的热更新。
- 通用服务器脚本系统或客户端 Lua 框架。
- 通过 Lua 增加全新的业务事件来源。新增事实仍需要 C# 业务代码接入。

## 4. 总体结构

```text
牌局 / 商店 / 仓库 / 收藏业务
            │
            ▼
    C# 产生权威 PlayerEvent
            │
            ▼
      事件可靠持久化与去重
            │
            ▼
    C# 投影为只读 Lua 事件表
            │
            ▼
 Lua 成就定义进行纯判定
            │
            ▼
 返回进度、临时状态和解锁结果
            │
            ▼
 C# 校验并在事务中保存完成与奖励快照
            │
            ▼
 目录 / 状态 / 解锁通知发送给客户端
```

Lua 不直接接触数据库、网络连接、玩家账户、钱包、库存、Unity 对象或业务服务。它只读取一次事件的不可变事实和该玩家在本成就中的当前状态，然后返回一个结果。

## 5. 职责边界

### 5.1 Lua 负责

- 成就 ID、名称、描述、类别、图标键、隐藏标记和排序。
- 展示目标、奖励内容和订阅的事件种类。
- 判断当前事件是否相关。
- 计算新的可见进度。
- 保存连续、分步或跨事件判定所需的成就私有状态。
- 明确回答本次是否应该解锁。

### 5.2 C# 负责

- 产生并可靠保存权威业务事件。
- 验证事件接收账号和服务端身份。
- 按事件种类选择需要执行的 Lua 定义。
- 为 Lua 构造只读事件和状态输入。
- 校验 Lua 返回值并在账户事务中应用。
- 保证事件消费幂等、进度持久化和完成不可逆。
- 在解锁时保存奖励快照。
- 在领取时校验余额、库存上限并真正发放奖励。
- 遮蔽未解锁隐藏成就的名称、说明、图标和奖励。
- 生成客户端展示目录、目录摘要和玩家状态。
- 在定义被删除后拒绝对应 ID 的领奖请求。

扑克最佳牌型计算、奖池归属等通用领域能力继续由 C# 提供。Lua 可以读取已经形成的事实，或调用只读的领域辅助函数，但不能改变正常牌局状态。

## 6. 文件组织与发现

服务器运行时配置继续归档在 `Configs/`，建议增加：

```text
Configs/
└─ Achievements/
   ├─ Common/
   │  ├─ poker.lua
   │  └─ progress.lua
   └─ Definitions/
      ├─ equip_new_namecard.lua
      ├─ pocket_aces_defeated.lua
      └─ strongest_split_pot.lua
```

- `Definitions/` 下每个 `.lua` 文件返回一个成就定义表。
- `Common/` 只保存共享纯函数，不参与成就目录发现。
- 文件名用于维护和日志定位，不是持久身份；持久身份始终是定义中的 `id`。
- 文件和定义不包含 `version` 字段。
- 服务端启动时加载全部定义；运行时由明确的重载入口重新加载整个目录。
- 加载器通过 `IAchievementScriptProvider` 获取脚本文本，第一阶段从文件系统读取。未来配置来源改为下载目录或其他资源载体时，不改变成就服务和 Lua 契约。

## 7. Lua 定义契约

每个定义返回一张表。第一版建议格式如下：

```lua
return {
    id = "equip_new_namecard",
    name = "锦衣加身",
    description = "换上一款新名片。",
    category = "通用",
    icon = "UI/Achievements/Cards-v1",
    hidden = false,
    sort_order = 10,
    target = 1,

    reward = {
        dollars = 1000,
        items = {}
    },

    events = {
        "collection.equipped"
    },

    evaluate = function(event, state, api)
        if event.account_id ~= state.account_id then
            return nil
        end

        if event.slot == "namecard"
            and event.item_id ~= "default"
            and event.item_id ~= event.previous_item_id then
            return {
                progress = 1,
                unlock = true
            }
        end

        return nil
    end
}
```

### 7.1 定义字段

| 字段 | 要求 |
| --- | --- |
| `id` | 永久进度键；沿用现有小写字母、数字、下划线和短横线限制。 |
| `name` / `description` | 玩家可见文案。 |
| `category` | 玩家筛选类别，客户端继续动态生成类别页签。 |
| `icon` | 客户端资源键；加载失败时回退默认图标。 |
| `hidden` | 未完成前是否使用统一隐藏展示。 |
| `sort_order` | 目录中的稳定排序值。 |
| `target` | 玩家可见目标，至少为 1。 |
| `reward` | 成就解锁后应保存的默认奖励，美金和物品均由 C# 在领取时发放。 |
| `events` | 需要订阅的稳定事件名称。 |
| `evaluate` | 纯判定函数。无变化时返回 `nil`。 |

奖励属于 Lua 成就定义的一部分。Lua 不调用发奖接口；C# 在 Lua 返回 `unlock = true` 时读取当前定义的奖励，校验后写入完成记录。之后实际领奖只使用完成时保存的奖励快照。

### 7.2 判定输入

`evaluate` 接收：

- `event`：本次不可变业务事实。
- `state`：账号 ID、当前进度和该成就的私有持久化数据。
- `api`：有限的只读领域辅助函数。

Lua 不能保留玩家状态到模块全局变量。需要跨事件保存的内容必须通过返回结果写入 `state.data`，由 C# 持久化后在下一次调用时重新传入。

### 7.3 判定结果

```lua
return {
    progress = 4,
    data_set = {
        last_hand_id = event.hand_id
    },
    data_remove = {
        "temporary_flag"
    },
    unlock = false
}
```

- `nil` 表示没有任何变化。
- `progress` 是新的绝对进度，不使用模糊的累计副作用；必须位于 `0..target`，越界视为脚本错误。
- `data_set` 和 `data_remove` 是对私有状态的修改建议。
- `unlock` 由 Lua 明确给出；C# 不因为 `progress == target` 擅自完成一个 Lua 成就。
- `unlock = true` 后，C# 将进度规范为目标值，保存完成时间和奖励快照，并停止以后对该账号执行该定义。
- Lua 不能返回完成时间、领取时间、账户余额或已经发放奖励等字段。

## 8. 事件接口

现有 C# `PlayerEvent` 继续作为数据库和业务层的权威事实。Lua 不直接接收 CLR 对象，而是接收稳定、只读的普通表。

第一批事件名称沿用现有来源：

| Lua 事件名 | 事实来源 |
| --- | --- |
| `table.stage` | 手牌阶段及结算快照 |
| `table.action` | 已接受的玩家行动 |
| `table.revealed` | 主动亮牌事实 |
| `shop.purchased` | 成功购买 |
| `inventory.used` | 成功使用物品 |
| `inventory.changed` | 变更后的库存快照 |
| `collection.equipped` | 实际装备切换 |

持久化事件自身仍可由 C# 维护兼容解码，但这些存储版本不暴露为 Lua 文件版本。C# 将不同历史载荷归一化成当前 Lua 事件形状。新增可选字段时旧脚本自然忽略；发生不兼容变化时随服务器代码一起更新相关脚本。

事件投影不得加入客户端协议。底牌、弃牌玩家牌型和完整奖池等敏感事实只能存在服务器内存与服务端持久化事件中。

## 9. 精简校验与错误处理

Lua 来自可信部署链路，因此第一版只执行以下校验：

- 全部脚本能够加载和编译。
- 每个定义都包含必需字段和可调用的 `evaluate`。
- ID 合法且全目录唯一。
- `target`、排序和奖励数值在 C# 可表示范围内。
- 奖励物品存在且数量不超过该物品上限。
- 订阅的事件名称已注册。
- Lua 返回的进度、状态和布尔结果能够转换为约定类型。

不需要为脚本建立复杂权限、签名或逐文件版本迁移。不过运行时仍应限制可用标准库，不向 Lua 暴露文件、网络、进程、数据库、钱包和任意 CLR 调用。这既保持职责清晰，也减少误调用业务接口的可能。

候选目录必须全部加载成功后才能替换当前目录。加载失败时继续使用旧目录。事件执行中的 Lua 异常应回滚该事件对应的成就事务，不写消费回执，并对该账号的事件重试进行退避，等待修复脚本并重新加载；不能把异常事件静默标记为已消费。

运行时应具备基础执行预算，至少能够中断明显的无限循环。这是防止开发失误拖住事件消费者，不是面向第三方脚本的安全沙箱。

## 10. 重载与切换

Lua 文件没有版本号，重载以“当前目录的完整内容”为准：

1. 暂停开始新的成就事件消费。
2. 等待正在执行的成就事务结束。
3. 从脚本提供器读取全部共享模块和定义。
4. 在候选运行时中编译、发现并执行精简校验。
5. 构造新的目录、事件订阅索引和客户端展示投影。
6. 原子替换当前运行时快照。
7. 恢复事件消费。
8. 如果客户端展示内容发生变化，广播新的目录摘要。

在重载前已经产生但尚未消费的事件，使用重载后的当前定义处理。系统不保存某个事件应该由哪一版 Lua 判定，也不回放已经消费的旧事件。

目录切换发生在事件边界，不允许旧定义在删除后继续完成一次延迟判定。服务器内只需要保留当前快照和一个最近的可用快照以处理加载失败；这不是对 Lua 文件建立业务版本体系。

## 11. 客户端目录与玩家状态协议

目录和玩家状态继续分开：

- 目录描述所有当前可展示的成就定义。
- 状态只描述当前账号的进度、完成时间、领取时间和已完成奖励快照。
- Lua 脚本、订阅信息、私有状态和服务端判定字段均不发送给客户端。

### 11.1 目录摘要

服务器在登录、重连以及目录内容变化时发送：

```csharp
public struct AchievementCatalogStamp
{
    public int SchemaVersion;
    public string CatalogRevision;
    public int DefinitionCount;
}
```

`CatalogRevision` 是当前完整展示定义的内容摘要，不是 Lua 文件版本。摘要包含隐藏成就解锁后使用的真实定义；因此隐藏成就的真实文案发生变化时也会刷新目录和状态。Lua 只修改判断逻辑而不改变展示内容时，`CatalogRevision` 保持不变，客户端无需重新下载目录。

`SchemaVersion` 表示网络字段结构。它只在客户端和服务器程序协议发生不兼容修改时改变，不随 Lua 内容更新。

### 11.2 目录请求

客户端按服务器地址保存当前目录缓存：

- 没有缓存或摘要不同：请求完整目录。
- 摘要相同：继续使用缓存，不发送目录请求。
- 分页期间摘要改变：丢弃半份结果，从第一页重新获取。
- 全部页面校验完成后一次性替换旧目录，不能向 UI 暴露半份目录。

目录规模较小时始终下载完整目录，不设计增量补丁。完整替换能够自然处理新增、修改、排序和删除。

第一阶段沿用当前进程内缓存。未来若需要持久化缓存，只能持久化共享的普通或遮蔽目录；已解锁隐藏定义和玩家状态必须继续按账号隔离。

### 11.3 玩家状态

玩家状态响应继续携带：

- `StateRevision`
- `CatalogRevision`
- 分页信息
- `AchievementStateView[]`

状态响应中的目录摘要用于兜底。若客户端状态请求期间目录已经变化，应放弃旧分页结果，并重新获取状态和目录。

缺少状态记录表示该成就进度为零且未完成。实现时可以继续发送完整状态列表，也可以改为稀疏状态列表；两种方式不改变目录协议。

### 11.4 解锁通知

解锁通知必须自包含：

```csharp
public struct AchievementUnlocked
{
    public string AccountId;
    public string CatalogRevision;
    public AchievementDefinitionView Definition;
    public AchievementStateView State;
}
```

客户端收到后：

1. 立即使用通知内的完整信息显示解锁横幅。
2. 合入当前账号的状态缓存。
3. 如果通知的 `CatalogRevision` 与本地不同，标记目录过期并后台获取完整目录。
4. 不因为目录尚未刷新而丢弃本次横幅。

隐藏成就完成时，通知中的 `Definition` 是真实定义。未完成隐藏定义在共享目录中继续使用统一遮蔽名称、说明、图标、目标和奖励。

### 11.5 图标

`Definition.IconPath` 只表示客户端资源键。客户端加载失败时使用统一默认成就图标，并继续显示其他信息。

本方案不通过 Mirror 消息传输图片，也不在目录响应内携带 PNG。未来 AssetBundle 方案可以让同一个资源键在下载新包后解析到新图标，或扩展为基于资源哈希的加载方式，但不改变成就完成和领奖协议。

## 12. 删除成就

从 `Definitions/` 删除脚本并成功重载后：

- 新目录不再包含该 ID。
- 客户端在完整替换目录后不再展示它。
- 事件路由不再执行它。
- 单项或批量领奖均只认当前目录；该 ID 的领奖请求返回未知成就或不可用。
- 数据库中已有进度、完成时间和奖励快照可以保留为不可达历史数据，不影响当前目录。
- 不设置退休状态、领取宽限期或自动补发。

删除是明确的运营行为。即使玩家此前已经完成但长期未领取，删除后也失去领取资格。

## 13. 与未来 AssetBundle 热更新的边界

未来 AssetBundle 方案预计覆盖牌面、成就图标、物品、名片及其他客户端配置和资源。为避免本次设计阻塞未来方案，成就系统遵循以下边界：

- 成就协议引用稳定的资源键，不关心该资源来自内置 `Resources` 还是后续下载的 AssetBundle。
- 客户端资源加载通过统一资源服务完成；成就 UI 不自行处理下载。
- 当前服务器下发的定义仍是展示权威来源。未来若部分展示配置随 AssetBundle 下发，需要在独立方案中明确服务器目录和客户端包之间的优先级。
- Lua 判定脚本只部署到服务器，不因为客户端配置打包而发送到客户端。
- AssetBundle 包版本、下载地址、校验和缓存策略不进入 Lua 定义契约。

## 14. 现有系统改造建议

### 14.1 新增核心组件

- `IAchievementScriptProvider`：读取共享模块和定义文本。
- `IAchievementLuaRuntime`：加载模块并执行定义函数，隔离具体 Lua VM。
- `LuaAchievementDefinition`：把 Lua 元数据投影成现有目录使用的定义模型。
- `LuaAchievementEventProjector`：把 `PlayerEvent` 转为只读 Lua 表。
- `LuaAchievementRouter`：按稳定事件名建立订阅索引。
- `AchievementRuntimeSnapshot`：组合运行时、目录和路由，支持原子替换。
- `AchievementCatalogStamp`：通知客户端当前展示目录摘要。

### 14.2 保留现有组件职责

- `PlayerEventRegistry` 和各事件来源继续负责事实与存储兼容。
- `AchievementService` 继续负责消费事务、完成时间、奖励快照和通知。
- `IAchievementRepository` 继续负责进度、消费回执和领奖事务。
- `AchievementClientCache` 继续合并目录与账号状态。
- 成就面板继续只消费 `AchievementView`，不感知 Lua。

### 14.3 目录摘要

从 Lua 加载出的展示定义按稳定顺序规范化后计算 SHA-256，作为 `CatalogRevision`。摘要至少覆盖：

- ID、名称、描述和类别。
- 图标键、隐藏标记和排序。
- 目标和默认奖励。

`evaluate` 函数内容、事件订阅和私有服务端字段不参与 `CatalogRevision`。修改这些内容只影响服务器判定，不触发客户端下载相同目录。

## 15. 迁移步骤

1. 引入 Lua VM 适配层、脚本提供器和候选目录加载器。
2. 建立 C# 事件到 Lua 表的投影，并固定第一批事件字段。
3. 让 Lua 定义与现有 C# 定义能够临时并存，但禁止重复 ID。
4. 先迁移购买、使用、装备和库存类简单成就。
5. 再迁移普通牌型、财富及累计类成就。
6. 最后迁移边池、诈唬、明确全下等复杂牌局成就。
7. 使用相同事件夹具并行执行 C# 与 Lua，比较进度、私有状态、解锁与奖励结果。
8. 全部现有成就通过一致性检查后，切换为 Lua 目录并删除具体 C# 成就类。
9. 增加运行时重载入口、目录摘要广播和完整解锁通知。
10. 更新 `Docs/Systems/Achievements.md` 和 `Docs/Systems/Achievements.md`，把新增成就流程改为 Lua 文件流程。

迁移期间 C# 与 Lua 的同 ID 定义不能同时进入正式目录，也不能对同一账号重复推进。

## 16. 验证要求

### 16.1 Lua 契约

- 合法定义能够发现、加载和订阅事件。
- 重复 ID、缺少字段、未知事件和非法奖励会拒绝整个候选目录。
- 无变化、进度变化、私有状态变化和解锁四类返回值均正确持久化。
- Lua 异常不会写消费回执或部分进度。
- 无限循环能够被执行预算中断。

### 16.2 迁移一致性

- 现有每项成就在相同事件和初始状态下，C# 与 Lua 结果一致。
- 覆盖弃牌、平分、边池、退款、断线、短码全下和重复事件等既有边界。
- 隐藏成就不会因 Lua 化向客户端泄漏真实条件或奖励。

### 16.3 重载

- 加载失败时旧目录继续可用。
- 成功切换后新事件只进入新目录。
- 新增成就不消费已经完成消费的历史事件。
- 删除成就后立即停止展示、判定和领奖。
- 仅修改判断逻辑时客户端目录缓存保持有效。
- 修改展示字段时客户端收到新摘要并完整替换目录。

### 16.4 协议与缓存

- 缓存命中时不重新下载目录。
- 摘要变化时分页获取完整目录。
- 分页期间再次变化时能够丢弃并重新开始。
- 新成就在客户端没有目录缓存时仍能立即显示完整解锁横幅。
- 图标不存在时回退默认图标。
- 切换服务器和切换账号不会混用玩家状态或隐藏定义。

### 16.5 环境

- Unity `2022.3.52f1c1` Editor 编译和 EditMode 测试。
- Linux Standalone 权威服务器加载、重载和事件消费。
- Windows 客户端、WebGL 客户端的目录缓存与解锁通知。
- 至少一服两端验证新增、修改、删除成就及领奖行为。

## 17. 实施完成标准

- 仓库中的具体成就条件不再由独立 C# 类型实现。
- 新增普通成就只需要增加一个 Lua 定义和必要图标，不修改注册表、消息处理器或 UI prefab。
- 服务器重载 Lua 后能够新增、修改和删除成就，无需重新构建服务器。
- C# 仍然是事件、进度、完成、奖励和领奖的唯一执行者。
- 客户端能够基于目录摘要复用缓存，并在目录变化后获取完整新定义。
- 任意新成就解锁通知都包含完整展示信息。
- 删除成就后不再展示且不能领奖。
- 缺失图标只回退默认图标，不影响其他功能。
- 本次 Lua 化不依赖尚未设计的 AssetBundle 热更新系统。
