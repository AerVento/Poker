# 房间生命周期与本手后离开

2026-09-05 更新：新增主动旁观/参战规则、空座轮转和请求版本校验，当前行为及最新 145 项测试与联机结果以 [SpectatorLifecycle.md](D:/GitHubRepos/Poker/Docs/SpectatorLifecycle.md) 为准。下方验证段落保留上一次离房功能的历史记录。

本次按“本手参与者在结算后离房”的规则补齐退出入口和服务器处理。预约离开只表达退出意图；本手仍可下注、跟注、弃牌、全下，不会因此提前弃牌或失去奖池资格。

## 状态与行为

| 情况 | 当前行为 |
| --- | --- |
| 等待房间内入座 | 校验登录身份、房间归属、空座和筹码；非房主准备后，由房主开始。 |
| 牌局中途入房 | 先作为无座旁观者加入；主动申请且有名额后，下一手开局前才入座。本手不发底牌、不允许下注，可立即离房。 |
| 无座旁观、筹码不足旁观 | 只接收旁观视图，可立即离房或继续旁观；余额够一个大盲且有名额时可申请下一手参战。 |
| 正在参加本手 | 左上角显示“本手后离开”，确认后服务器记录预约；按钮变成“取消离开”，并显示结算后返回大厅的提示。 |
| 已弃牌或已全下 | 仍属于本手参与者，退出必须等待结算。全下玩家的主池、边池权益照常保留。 |
| 本手已结算、下一手倒计时 | 可以直接离开；服务器开始下一手前会再次处理预约和检查人数。 |
| 本手中掉线 | 保留本手座位；轮到掉线玩家时沿用自动过牌／弃牌规则，已全下不会自动弃牌。 |
| 本手中重连 | 验证账户后恢复原座位和服务器现有状态；已经发生的弃牌不会撤销，预约离开也不会因重连取消。 |
| 预约后持续离线 | 服务器在结算后照样移除玩家并清理账户的上次房间关联，不依赖客户端在线。 |
| 未预约的掉线玩家 | 结算后释放其参赛座位为旁观成员，保留上次房间关联；再次恢复进行中房间时仍为无座旁观者，需要主动申请下一手参战。 |
| 房主离开 | 真正移除时才移交房主；下一手合格参战人数不足两人时，参赛者返回房间等待页，全部旁观者返回大厅；成员全部离开才删除房间。 |

## 实现位置与顺序

- `RoomSeatInfo.LeaveAfterHand` 记录预约，`RoomDepartureService` 统一判断立即离房／排队／取消。请求中的玩家名字不作为身份依据。
- `GameManager.RequiresDeferredLeave` 同时检查本手是否进行中及该玩家是否参与本手，避免把弃牌玩家误当成旁观玩家；下一手资格判断排除预约玩家。
- `NetworkRoom.OnRoomRoundEnd` 在账户结算成功、发送结算结果与余额后，完成预约退出，然后同步座位、移交房主并检查下一手人数。
- 清除上次房间关联先落库再移除成员。写入失败时保留房间关联并提示重试；预约玩家不会被发进下一手。
- `PlayerLeaveRoomResponse` 明确区分已离开、已预约、已取消和失败。GamePanel／RoomPanel 等待服务器确认后才切换界面。
- 离房后关闭相关结果与确认弹窗，停止牌桌计时显示；房间号用于过滤迟到的牌桌同步、倒计时及结算通知，避免旧消息重新打开牌桌。
- 阶段推进和下一手倒计时在异步等待后核对服务器运行版本、牌局对象及手牌标识，防止已退出的流程继续推进旧房间。

消息修改涉及 `PlayerLeaveRoomRequest`、新增 `PlayerLeaveRoomResponse`、`GameInfoSync`、`RoundResultNotification`。房间及客户端牌局信息仍用现有 JSON 序列化，Mirror 生成其他字段的读写。客户端和服务器需要使用同一批更新后的构建。

## 上一次离房功能验证（历史记录）

- Unity `2022.3.52f1c1` EditMode：119 项全部通过，包含新增的 11 个离房规则用例和 2 个 UI 生命周期用例。
- Windows 独立构建：一个服务器和三个客户端，完成登录、建房、入房、准备、下注、河牌、两手结算、下一手倒计时。
- `departures` 场景额外覆盖预约并取消、中途入房等待者离房再加入、两手之间离房再加入、预约者断线返回标题页并重连、保留预约、结算自动返回大厅。退出请求故意携带错误的玩家名字，以验证服务器使用认证身份。
- 最终三个账户合计 30,000 筹码，账本一致，未结算牌局为零，已离房账户没有残留上次房间关联。
- Editor 内运行 Game.unity，检查 1920×1080 和 1600×1000 下的退出按钮、预约提示、确认弹窗；通过 EventSystem 射线和点击事件确认按钮未被背景遮挡。
- 最终构建中的离房按钮及文字同步断言通过；Game 场景与 21 个 UI／管理器预制体检查未发现 Missing Script 或损坏引用。
