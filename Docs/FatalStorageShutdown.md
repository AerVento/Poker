# 服务器存储异常时停服

更新：2026-09-05。按当前项目规模采用尽力通知、立即停止游戏、关闭服务器的处理方式；此前讨论的结算重试和待结算队列方案不再采用。

## 当前行为

1. 正式服务器的账户仓储统一经过 GuardedAccountRepository。数据库初始化、账户读取/写入、下注、盲注、结算、房间关联、密码迁移及会话操作出现未预期异常时，触发一次停服。结算数据被仓储拒绝同样停服。
2. 立即关闭所有牌局计时器、清除推进任务所依赖的牌局引用，并停止接受后续业务请求和账户仓储访问。停服过程中不继续发牌、不重试入账，也不尝试再次写入退款。
3. 向包括未登录连接在内的在线连接发送固定原因通知，留出 500 毫秒供网络发送，然后关闭 Mirror 服务。独立无界面服务器以退出码 1 结束进程；Editor/本地 Host 停止网络服务，保留编辑器或客户端。
4. 收到通知的客户端主动断开，关闭房间、牌桌及原有弹窗，回到标题页，显示“服务器已停止服务”：

> 服务器数据保存失败，服务已停止。请等待服务器恢复后重新登录。

通知原因只发送枚举，客户端不展示数据库路径、异常堆栈或内部牌局状态。通知优先于普通断线/连接失败提示；保留本地登录凭据，恢复服务后可重新登录。

密码错误、用户名重复、筹码不足、无效玩家输入等正常业务拒绝不会触发停服。

## 恢复与限制

此次没有新增备份日志、持久重试任务或结算恢复队列，不承诺未成功保存的胜负结果已被记录。

修复存储故障并重新启动服务器后，沿用现有 SQLite 初始化规则：退还数据库中仍为 Active 的手牌已记录投入；已成功结算的手牌不会再次退款。重复初始化不会重复退款。内存房间不会跨进程恢复。

停服通知是尽力发送。若服务器被强制终止、进程直接崩溃或网络已断，客户端无法取得具体原因，只能显示普通断线提示。服务器关闭后才尝试连接的客户端也只能看到连接失败。
