# 名片美术与文字安全区标准

名片是一张完整的「主题背景 + 细边框」图片。自定义名片直接替换经典绿色底板；姓名、余额、倒计时、D / SB / BB、断线和操作状态由独立 UI 绘制。默认「经典」仍免费拥有，保留原有外观；未知款式或缺图回退经典。

## 尺寸与边界

以下像素按 2048 × 768 原图计，缩小时全部等比换算。

| 项目 | 原图标准 | Unity 导入后上限 |
| --- | --- | --- |
| 比例与尺寸 | 8:3，最大 2048 × 768，推荐使用此尺寸 | 1024 × 384 |
| 亮色边框、实体饰件、宝石与明显光晕 | 距最近一条外边缘最多 64 px | 32 px |
| 常规边线 | 建议 12～32 px，装饰尽量控制在 48 px 内 | 6～16 px，装饰建议不超过 24 px |
| UI 安全区 | 四周各内缩 96 px | 四周各内缩 48 px |
| 边框与 UI 之间缓冲 | 至少 32 px | 至少 16 px |

文字区域为原图 `(96, 96)` 到 `(1952, 672)`。亮色装饰不能进入 `(64, 64)` 到 `(1984, 704)` 的内矩形，四角花饰也遵守这一规则。低对比度的主题背景可以贯穿内矩形。以 384 × 144 的名片显示为例，装饰最多向内 12 px，UI 从四周 18 px 起排布。

程序中的统一数值位于 `Assets/Scripts/UI/Namecards/NamecardLayout.cs`。不要针对某张图片单独挤压姓名或金额；图片不符合标准时，应调整图片。

## 同主题的 4:3 专用版本

横向版本保持 2048 × 768（8:3）；紧凑格子使用重新构图的 1024 × 768（4:3）图片，不能直接压缩横图，也不要裁掉原图两端来假装适配。两种图片属于同一商品 ID，保留同样的主题、调色、背景内容和边框材质，只调整画面构图。

4:3 的交付 Sprite／运行时纹理尺寸为 1024 × 768，Max Size 仍是 1024。本次内置生图工具实际输出 1448 × 1086（精确 4:3），源 PNG 原样保留，Unity 等比缩小到 1024 × 768；不是把 8:3 横图压扁。以下 4:3 像素阈值按目标 1024 × 768 画布计。亮色装饰建议在外侧 48 px 内、绝对上限 64 px，UI 四周至少内缩 96 px；该规格沿用相同的 768 px 原图高度，因此边框像素上限不变。4:3 内容安全区为 `(96, 96)` 到 `(928, 672)`。

每款名片的两张图命名为 `<商品ID>-wide.png` 与 `<商品ID>-4x3.png`，由同一个远程数据 `NamecardArtworkSO` 引用。历次生成的提示词与预览在 `ArtSources/Namecards/`。

4:3 源图允许不超过 2048×1536，但必须是精确 4:3；实际导入不超过 1024×768。商品 Inspector 同时预览并校验两张图，参考线分别使用各自的标准画布。缺少某个比例时运行时会回退另一张；双图都缺失或未知 ID 则显示经典。

`NamecardAppearance` 根据美术槽的实际宽高，选择相对比例更接近的图片，然后等比显示。当前 Player8 使用 4:3，Player4 / Player16、房间与商城使用宽版。图片未完全铺满格子时，文字安全区也以实际显示的图片边界计算；不会把根节点强制设为图片比例，也不会在运行时更改各档字体。接入时曾将 8 / 16 人档的金额字号下限补调为 14 / 12（最终数值以各 prefab 为准），避免极大金额在安全区内被省略。

## 背景内容与可读性

- 内部必须是不透明的完整主题背景，不能只剩黑底、透明洞或孤立的边框。小圆角外可透明，也允许深色不透明圆角底由 UI 遮罩裁切。
- 使用有颜色的暗部、柔和渐变和较大的主题轮廓。在缩小的玩家列表中仍能分辨星云、冰川、玉石等主题。
- 文字区域保持低对比，避免白色光核、高亮日冕、锐利闪光、密集粒子和密集纹线。背景只提供氛围，暖白姓名、金色余额与状态标识应一眼可读。
- 背景优先使用约 12%～28% 的显示亮度作为制作参考，不把它当作严格的颜色通道阈值。最终必须叠加真实 UI 在实际显示大小下检查。
- 图中不要画姓名、价格、D / SB / BB、按钮、占位符、参考线或文字，这些均由 UI 提供。

## 配套物品图标

每款名片除宽版和紧凑版外，还必须同时制作一张 `Assets/Sprites/Items/Namecards/namecard-<商品ID>.png`，默认款也适用。图标采用统一倾斜圆角名牌卡构图，保留主题主色与简化标志；具体风格、1024×1024 透明 PNG、导入、生成记录和小尺寸验收要求见 [UI 规范第 8.4 节](UIConvention.md)。主题变化时同步更新图标，不能直接缩小名片原画代替。

## Unity 导入

PNG 使用 Sprite (2D and UI)、Single、Full Rect、Max Size = 1024、关闭 Mip Maps、Wrap Mode = Clamp、Non Power of 2 = None。分别保持 8:3 / 4:3，不能拉伸图片来补救比例或边框。带透明通道的 PNG 打开 Alpha Is Transparency。平台 Override 不能把纹理上限调高；Unity 自动生成的 `.meta` 必须一起保留。

替换美术时直接覆盖原 PNG（保留 `.meta` 与 GUID），不改变商品 ID、价格、已购库存或装备记录；旧版放到 `ArtSources/Namecards/`。

## 在工程中检查

1. 选择商品 SO。Inspector 中「名片留白检查」分别显示宽版和紧凑版：黄线为 64 px 边框上限，青线为 96 px UI 安全区。亮色实体装饰应在黄线外，暗色主题背景可在黄线内。
2. 执行 `Poker → Shop → Validate Namecard Artwork`，检查源图比例、最大尺寸、Sprite 模式、纹理上限、平台覆盖和 Mip Maps。该检查不能自动识别画中的花饰，边框内容仍需对照参考线目检。
3. 执行 `Poker → UI → Preview Namecard Shop` 检查实际商品预览、姓名、金额和装备状态。分页仍为每页 4 款。
4. 运行 `Assets/Scenes/Game.unity`，分别看等待房间与牌桌，检查长姓名、六位余额、百万 K 显示、D 与 SB 同时出现、断线标识、操作金额、倒计时和准备状态。
5. 检查经典、自定义款、未知 ID 回退，以及从自定义换回经典。自定义款下的旧绿色 Image 应禁用，准备或轮到操作时不能重新露出绿色底板。

商城、等待房间与牌桌的文字都在 `NamecardContent` 中。等待页的房主和「已准备」位于内容区下方；牌桌的姓名、金额、角色与操作状态位于安全区中，具体字号和排列以当前玩家数量对应的 prefab 为准。状态标识独立于主题背景，不再用覆盖整张名片的旧金色矩形外框表示状态。

商品配置与显示规则见 [名片](../Systems/Namecards.md)，新增流程见 [poker-cosmetics](../../.agents/skills/poker-cosmetics/SKILL.md)。
