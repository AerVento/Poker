# Lua 规范

本规范适用于所有随远程内容动态更新的 Lua 代码，目前即礼物特效。脚本接口、沙箱与预算见 [礼物](../Systems/Gifts.md)，包的依赖、版本判断与下载规则见 [远程资源](../Operations/RemoteArtwork.md#包依赖与版本)。

## 放在哪里

| 代码 | 位置 | 进入的包 |
| --- | --- | --- |
| 礼物入口模块 | `Assets/Scripts/UI/Gifts/Lua/<礼物大驼峰>.lua.txt` | 该礼物的包 `gifts/<物品 ID>`，与它的美术、音效一起发布 |
| 共享模块 | `Assets/Scripts/UI/Gifts/Lua/Shared/<模块>.lua.txt` | 共享 Lua 包 `lua/shared` |

- 只属于一个礼物的逻辑写在该礼物的入口模块里；两个及以上礼物使用、或明显通用的逻辑放进 `Shared/`。入口模块不能放在 `Shared/`。
- 写新逻辑前先看 `Shared/` 里有没有能复用的模块。
- 原本只属于某个礼物的逻辑被第二个礼物用到时，把它拆成独立模块，用 `git mv` 连同 `.meta` 放进 `Shared/`。
- `Shared/` 下的全部 `.lua.txt` 由 `Poker/Remote Artwork/Prepare Catalogs and Groups` 自动收集进共享包根资源 `Assets/RemoteContent/lua/Shared.asset`，不要手动编辑其模块列表。
- 模块名是文件名去掉 `.lua.txt`，在一个礼物能取到的全部模块（入口与所依赖包）中必须唯一。
- 共享包变大或出现只服务一类礼物的大块逻辑时，再按用途拆成多个包（如 `lua/touhou`），每个包有自己的文件夹和版本号；拆包需要在 `RemoteArtworkBuild.Prepare` 中注册新包。

## 依赖声明

- 礼物用到共享模块时，在礼物根资源 `GiftEffectSO` 的 `_dependencies` 中写一条：地址 `lua/shared`，最低版本写成 `主.次`，取当前共享包版本的前两段（共享包 `1.3.2` 写 `1.3`）。
- 礼物根资源不能直接引用共享模块文件，否则共享模块会被复制进礼物包；`GiftEffectSO` 也没有这样的字段。
- `require` 只能取到本礼物的入口模块和所依赖 Lua 包中的模块，取不到其他礼物的脚本。

## 版本号

共享包的版本号是 `Shared.asset` 的 `_version`，格式 `主版本.次版本.修订号`。修改 `Shared/` 下任何文件后，按下表修改：

| 改动 | 版本号变化 |
| --- | --- |
| 修复问题，对外接口不变 | 修订号 +1 |
| 新增模块、函数或可选参数，旧用法仍然有效 | 次版本 +1，修订号归零 |
| 删除或改变已有模块、函数、参数、返回值或行为 | 主版本 +1，其余归零 |

- 对外接口是模块返回的表中的名字，以及这些函数的参数、返回值和行为。
- 优先做向后兼容的修改：新增函数或可选参数，而不是改变已有函数。
- 必须升主版本时，同一次修改中更新所有依赖该包的礼物代码和 `_dependencies`（改成新的主版本）；构建会拒绝不满足的依赖声明。
- 用到共享包新增的功能时，同时把礼物的最低版本提高到该次版本，否则浏览器中较旧的共享包可能缺少这个功能。

## 锁文件

`Assets/RemoteContent/packages-lock.json` 记录每个有版本号的包上一次内容构建时的版本号、内容哈希和对外名字（Lua 包为每个模块及其返回表中的名字）。校验与构建时比较，不满足以下规则就失败，报错写明至少应改成的版本：

| 变化 | 版本号至少要 |
| --- | --- |
| 内容变化 | 修订号 +1 |
| 新增模块或对外名字 | 次版本 +1 |
| 删除模块或对外名字 | 主版本 +1 |
| 任何情况 | 不低于锁文件中的版本 |

构建成功后锁文件自动更新，与内容改动一起提交。函数名字不变但行为改变的破坏性修改无法自动发现，必须按上表人工升主版本。

## 编写约束

- 模块返回一个表；共享模块只放函数和不可变参数，每次播放的状态留在礼物的 `build` 内部。
- 文件使用 UTF-8。修改后在礼物预览中检查所有依赖该模块的礼物。

## 跨礼物状态与清理

打进同一个共享包表示代码只发布一份，不表示 `require` 的返回表在所有礼物中是同一个实例。当前各礼物定义的模块环境与 require 缓存独立，继续保持共享模块只包含函数与不可变参数。

- 必须跨礼物协调时，用 `g.sharedState('功能名称')` 显式取得客户端 Lua 运行期共享状态。只在实际播放回调中读写，不在模块加载、build 或拖动预览时改变共享状态。
- 共享表只保存必要的 Lua 数据和数字句柄，不保存某次播放的 `g`、回调闭包或资源对象。进入新播放时检查句柄是否仍有效；场景退出或异常清理后旧句柄可能失效。规则改变时明确处理已有状态的兼容。
- 单次播放是否已加入、是否已释放等状态仍放在 build 的闭包里。用 `g.onStop` 或 `g.onAudioStop` 在 build 中登记清理，不能只依赖时间线末尾，因为特效可能提前取消。
- C# 只提供音频句柄、渐变、资源持有及兜底清理等通用能力。具体礼物的互斥、引用计数、续播和循环规则写在共享 Lua 模块；`TouhouMusic` 通过现有 `lua/shared` 包发布。
