# 成就系统

新增成就只需在 `Assets/Scripts/Game/Achievements` 下新增一个 public C# 类，牌局类继承 `HandAchievement`；其他成就继承 `Achievement` 并实现所需 `IAchievementHandler<TEvent>` 接口，使用默认无参构造。Unity 自动生成 `.meta` 后一并提交；无需修改注册表、网络消息、面板或 prefab。运行时从 `Assembly-CSharp` 自动发现成就，构建时 `AchievementLinker` 自动保留这些类和构造函数，支持 IL2CPP 裁剪。

```csharp
using Game.Achievements;
using Game.Network;
using Game.Tasks;

namespace Game.Achievements
{
    public sealed class PlayTenHandsAchievement : HandAchievement
    {
        public override string Id => "play_ten_hands";
        public override string Name => "初入牌桌";
        public override string Description => "完成 10 手牌。";
        public override string Category => AchievementCategories.General;
        public override string IconPath => "UI/Achievements/Default";
        public override int Target => 10;
        public override Reward Reward => new Reward(500);

        public override void Evaluate(AchievementContext context, string accountId, AchievementProgress progress)
        {
            if (context.Stage == GameStage.RoundOver)
                progress.Count++;
        }
    }
}
```

上面的类仅是文档示例。当前共有 32 个成就：原有「葫芦之上」、17 个财富／牌型／特殊成就、11 个账户操作与牌局成就、2 个诈唬主题成就，以及隐藏成就「一掷成灰」。所有成就的现金奖励均发放为美金。

## 定义字段

| 字段 | 说明 |
| --- | --- |
| `Id` | 永久身份；小写字母、数字、下划线或短横线，最长 64。发布后不可修改，否则视为另一个成就。 |
| `Name` / `Description` | 名称和简短描述，共用于列表和顶部横幅。 |
| `Category` | 默认「通用」，示例为「特殊」。也可直接返回新类别名称，面板自动增加页签。 |
| `IconPath` | Unity Resources 路径，不带扩展名。默认 `UI/Achievements/Default`。 |
| `SortOrder` | 列表顺序，较小的排在前面；相同则按 ID 排序。 |
| `Target` | 目标进度，默认 1。 |
| `Reward` | 美金和物品，可组合；例如 `new Reward(1000, new[] { new ItemStack("devil-contract", 1) })`。`Reward.Chip` 是为兼容既有持久化数据保留的字段名，当前语义为美金。物品必须存在于服务器物品目录。 |

自定义图标：把 Sprite 放到任意 `Resources` 子目录，并在类中覆盖 `IconPath`。图标缺失时回退默认徽章，不会阻止成就显示。所有徽章统一为墨绿珐琅底、暖金属圆框和浮雕主体；Default 和 FullHouse 已重绘并保留原路径与 GUID。保留生成原图，Unity 导入上限为 256，禁用 mipmap 并保留透明通道。同系列成就可复用图标。新增图标前阅读 `Assets/Resources/UI/Achievements/AGENTS.md`。UI 的 `Poker/UI/Build Achievement UI` 菜单会重建 UI prefab，不覆盖已有图标，也不再程序生成旧版扁平图标。默认图标丢失时应恢复资源或按美术规范重新生成；日常增加成就无需执行此菜单。

## 多来源事件

现已支持牌桌 `table`、商店 `shop`、仓库 `inventory`、收藏装备 `collection`。来源和 UI 成就类别是不同概念：来源用于记录业务事实，类别仍由成就定义的 `Category` 决定。新增来源、事件版本、事务写入和多事件订阅方法见 [成就事件扩展说明](AchievementEvents.md)。

商店覆盖普通物品、名片和牌面购买；仓库覆盖普通使用、礼物批次消耗及库存变更；收藏覆盖实际装备切换；牌桌同时覆盖阶段快照和有效行动。服务端只在成功业务事务中写入事件，失败、重试回执和相同装备重选不会重复推进成就。

## 编写判断逻辑

`Evaluate` 收到当前账号、本手截至当前时点的不可变快照，以及该账号这个成就的可写进度。成就定义是共享实例，不要在定义类字段里保存某个玩家的状态。复杂分步状态写入 `progress.Data`（字符串字典），系统随进度一起持久化；达到目标后自动完成并停止后续判断，领取后也不重置。

事件在翻牌前发牌和盲注完成、翻牌、转牌、河牌以及手牌结算时产生。普通下注和 all-in 自动发牌使用相同入口。下一手用新 `HandId` 再发送翻牌前事件，结算不会等待下一手开始。

- `context.Players`：本手参赛者，含已弃牌和断线者；旁观者不参与。包括底牌、最佳牌型及比较等级、盲注位置关联、手牌起始筹码、可用于本手的筹码、投入、弃牌/all-in/断线状态、奖池奖金和退款。
- `context.Streets`：截至当前的各阶段快照，包括公共牌与当时玩家状态。
- `context.Actions`：截至当前的有效行动，包含玩家、阶段、行动序号、操作类型、阶段投入、剩余筹码、行动前筹码、本次投入和断线状态。盲注在初始快照中表示。
- `context.Pots`：结算时主池/边池的金额、有效争夺者与赢家。退款单列，不是赢得奖池。
- `context.Showdown`：本手是否摊牌；全员弃牌后的无争议获胜为 false。

「葫芦之上」只在结算且摊牌时判断：玩家最终最佳牌型必须恰好是葫芦，赢得的某个奖池里存在另一位未弃牌的有效争夺者，其最佳牌型也是葫芦且严格小于自己。只平分、仅退款、对手已弃牌、最终升级为四条、没有共同争夺同一个奖池，均不计入。多人中若两位并列赢家击败第三位较小葫芦，两位赢家都可达成。

## 保存、领奖和同步

全部判定在服务器执行；牌局上下文绝不加入客户端协议。普通成就会向客户端提供名称、图标、进度、完成／领取时间及奖励。未解锁隐藏成就只提供类别及统一遮蔽信息。

数据库 schema 10 增加成就状态、上下文事件和逐账号消费记录。结算上下文和手牌净结算处于同一事务，事件处理记录和进度也处于同一事务；同一 `HandId + 阶段` 不重复计数。重启可继续消费已保存的事件，未结算且被中止的手牌不会产生结算成就。进度以 `AccountId + AchievementId` 永久保存，不刷新、不删除。

完成时保存奖励快照及物品数量限制；之后修改成就奖励，不会改变已经获得的待领取奖励。奖励、美金流水、物品和领取状态原子提交；失败全部回滚，余额或库存达到上限时仍保留待领取奖励。玩家在大厅、房间、旁观、手间等待或牌局中均可领取。重复领奖只返回已领取。

## 隐藏成就与列表顺序

定义覆盖 `Hidden => true` 后即为隐藏成就。未解锁时，目录投影不会向客户端发送真实名称、描述、图标、目标或奖励，统一显示「隐藏成就」「继续游戏以解锁」、`Hidden-v1` 图标、`?? / ??` 进度和 `??` 奖励；类别仍正常显示和参与筛选。完成状态会附带真实定义，列表和解锁横幅立即显示实际内容。

列表稳定按以下优先级排列，组内保持目录原顺序：已完成未领取、已完成已领取、普通未完成、隐藏未完成。页签底部的「一键领取」覆盖该类别全部可领奖励；「全部」页签覆盖所有类别。服务端在一个账户事务中汇总奖励并一次发放，随后同时标记各项已领取；重试不会重复发放。

首个隐藏成就是特殊类「一掷成灰」，奖励 $10,000 美金。仅接受玩家明确选择的 `PlayerOperationType.AllIn`，要求行动前剩余筹码至少 $50,000，并且该次 AllIn 的投入扣除最终未跟注退款后仍至少 $50,000；Bet、Raise、Call 耗尽筹码、盲注耗尽和断线自动操作都不算。结算时玩家不得赢得任何主池、边池或平分池，只有退款也不算赢池。

顶部横幅按完成顺序排队，使用不占用导航和鼠标输入的系统层。显示完成后客户端确认；断线前未确认的通知会在重新登录时补发。成就面板由标题页「成就」入口进入，包含「全部 / 通用 / 特殊 / 牌型 / 财富」页签；后续类别仍按服务端目录自动生成，无需手工维护注册表，类别栏可横向滚动。面板使用 Vertical Scroll View，每行一个成就。列表采用分页协议，不随成就数量增长成单个无限消息。

## 客户端缓存

成就目录与玩家状态现已拆分：目录首次打开时加载并保留在本次客户端运行内存中；状态在登录及收到解锁通知时刷新。普通进度变化仅推送一个 bool 过期提示，下一次打开面板或手动刷新时才请求状态，无变化则直接使用缓存。领奖成功由回包更新该项状态。详细协议、服务器合并通知、分页竞态及账号隔离见 [成就客户端缓存](AchievementCaching.md)。

判定口径：

- 净盈利 = 奖池奖金 + 未跟注退回筹码 − 本手总投入。累计仅累加正数，亏损不扣减；单手成就展示历史最高净盈利。进度到达目标即封顶，使用 `long` 运算避免大额结算溢出。成就奖励、赠送等不会生成盈利进度。
- 牌型成就要求最终摊牌且未弃牌，不要求赢。使用最佳五张牌的准确类别，不向较低类别连带解锁；允许全部使用公共牌。
- 大鱼成就只比较同一获胜奖池的有效争夺者：至少两位未弃牌败者的牌型类别不同；仅点数大小不同不够。自己必须击败这两人且为同花及以上；可与另一位赢家平分获胜。不同边池的败者不能拼凑条件。
- 一对 2 要求最佳牌型恰好为一对且对子为 2；底牌不必是 22。主池、边池或平分任一实际奖池均可，仅退款不算。
- 皇家同花顺在翻牌／转牌／河牌快照中立即判断；当时未弃牌即可，之后弃牌不撤销。已弃牌后公共牌才补成皇家同花顺不算。该成就不要求摊牌；若之后也摊牌，可同时解锁牌型类同花顺。

- 双听牌检查底牌和五张公共牌共七张，未弃牌且最终摊牌。最多同一花色恰好四张，同时至少一个顺子的五个不同点数恰好出现四个；允许卡顺及 A2345。已组成任意顺子或同花则不满足，不要求听花与听顺必须由同一张补牌完成。双听牌必须在 Flop 或 Turn 结束时已经出现；仅由 River 牌造成的双听牌不算。
- 最强对决可在任意主池或边池达成，同池必须恰好两位并列赢家，其他失败争夺者可以存在；两位均可解锁。正常奇数筹码分配不影响平分资格，三人平分不算。

本批复用现有 Cards-v1、Champion-v1、Wealth-v1、FullHouse 图标。按用户约定未运行自动化、联机或 UI 交互测试，未执行构建；既有章节的通过记录不代表本批结果。

## 诈唬主题成就（2026-09-10）

定义在 `BluffAchievements.cs`，均属于特殊类，奖励各 $10,000。订阅现有牌桌结算事件，沿用永久进度、消费去重和独立领奖，无需新增事件或网络字段。

- 兵不厌诈仅在未摊牌结算且实际赢得奖池时判断，至少已有三张公共牌。只比较本轮下注中弃牌的对手；赢家与这些弃牌者均按结束时实际发出的同一组公共牌计算最佳五张牌，不补发尚未出现的牌，也不使用弃牌当时的旧牌型。翻牌前结束、仅退回未跟注筹码、正常摊牌胜利都不算。弃牌者的底牌仅用于服务端判定，不新增客户端泄露。

## 主动亮牌补充判定（2026-09-11）

其他玩家全部弃牌后，获胜者在结果窗口主动公开底牌时，服务端发布每手每账号唯一的 `HandCardsRevealedEvent`。事件只保存实际已经翻出的公共牌和该玩家两张底牌。三张以上公共牌时，`ShowdownHandAchievement` 系列会用这些牌计算当前最佳五张牌并补充对应牌型成就；翻牌前只有两张底牌时不组成五张牌型，因此不推进。

主动亮牌不会改变该手仍属“对手弃牌结束”的事实，也不会再次计入胜场、盈利、奖池、击败对手、诈唬或其他结算成就。事件 ID 固定为 `handId:reveal:accountId`，重复请求不会重复推进。
