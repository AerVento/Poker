# 旁观、下一手参战与座位生命周期

更新：2026-09-05。本文描述当前实现；完整逐项测试见 [测试用例总表](D:/GitHubRepos/Poker/Docs/TestCaseInventory.md)。第二项审查问题已采用存储异常停服策略，见 [FatalStorageShutdown.md](D:/GitHubRepos/Poker/Docs/FatalStorageShutdown.md)。

## 用户场景与覆盖

| 场景 | 当前 UI 和服务端行为 | 实际覆盖 |
| --- | --- | --- |
| A 建房、B 入房、准备、开始 | 大厅创建房间、房间行加入、准备、房主开始；服务端验证身份、筹码和人数 | EditMode；两套一服三端测试均调用正式 UI 按钮事件 |
| C 在对局中加入旁观 | 点击大厅的进行中房间即可进入，满桌也允许；不分配座号，不发底牌，下注控件隐藏 | 满额两人桌加入 C；UI prefab 与服务端投影断言 |
| 不泄露其他人的底牌 | 牌局快照只含自己的底牌；旁观者没有底牌；旁观结算保留已经公开的摊牌底牌；弃牌和未摊牌直接获胜仍不公开 | 投影测试、结算复制测试、旁观快照与 UI 卡牌状态断言 |
| 旁观者离开 | 点击“离开房间”，确认服务器清理房间关联后回大厅；取消其参战预约 | 专项联机 C 离开再入；预约者离开单测 |
| 旁观者下一手参战 | 有名额、余额至少一个大盲时点“下一手参战”；显示“已申请下一手”，下一手开局前才分配座号并发牌 | 专项联机第三手 C 正式参战；延迟入座单测 |
| 人满不允许申请 | 按钮显示“参战名额已满”并禁用；伪造网络请求仍被服务端拒绝 | 满桌 UI 单测；联机强制发送一次申请并断言 TableFull |
| 继续旁观 | 不申请就持续旁观；“继续旁观”可以取消已提交的下一手预约 | 三手持续旁观单测；联机跨手旁观；取消预约 UI 与服务单测 |
| 参战者下一手转旁观 | “本手后旁观”预约，“取消转旁观”撤销；本手行动、底牌和奖池权益保留，结算后释放座位 | A 转旁观、C 替补的联机流程；弃牌/全下/重连单测 |
| 下一手不足两人 | 取消续局；剩余参赛者回房间页；全部旁观者解除房间关联并回大厅 | 专项第三手后 B 回房间，A/C 回大厅；服务端最后无残留关联 |

“本手后离开”仍是独立操作，结算后直接返回大厅；它与“本手后旁观”去向不同。弃牌和全下都仍然属于本手参战者，不能跳过结算立即释放座位。

人数上限仅限制参战名额，不计旁观人数。服务端同时预留下一手名额，防止多人同时申请超额。本手已全下且暂时余额为零的玩家仍占参战名额，不能提前按余额零把位置让出。实际开局时会重新检查在线状态和余额。

预约转旁观/离房释放的是下一手名额，本手座位保留到结算。如果别人已预约该名额，原玩家取消预约会收到名额已满提示，当前预约保持不变。新申请者“继续旁观”或离房后会归还预留名额。

## 座位与盲注

- 座位使用从 0 开始的编号。NextSeatIndex 只向后增长；旁观及下一手预约没有座号，正式入座时才取新号。
- 离开或转旁观后，原座号为空；压缩前不会分给别人。人数上限与座号最大值分别维护。
- 庄位/大小盲按现存合格玩家的环绕顺序推进，跳过空位，从末尾绕回开头；保留多人转单挑的轮转处理。
- 空座比例 = （已分配座号总数 − 当前占用座数）/ 已分配座号总数。严格超过 50% 才压缩，恰好 50% 不压缩。
- 仅下一手开局前压缩。按旧座号排序重新连续编号，并映射原庄位/大盲位置，使重编号不改变玩家的相对顺序。进行中的手牌不压缩。

测试覆盖不复用旧号、旁观后重新入座取新号、50%/超过 50% 两个边界、活动手禁止压缩，以及座号 0/2/4 的连续六手大盲依次 4/0/2/4/0/2。

## 拒绝过期操作

下注、加注、跟注、过牌、弃牌和全下请求携带 HandId + TurnId。服务端在规则处理和内存筹码扣减前检查，任何已结束行动机会、上一街、上一手或重复请求均拒绝；每个已接受动作和阶段切换都会更新 TurnId。客户端也过滤旧回应，避免过期错误干扰当前操作。

加入下一手、继续旁观、预约/取消转旁观另外携带 HandId 和玩家意图版本 ParticipationRevision，旧版本不能覆盖较新的选择。网络处理器仍以已登录连接映射身份，不能信任客户端提供的名字或座号。

测试实际先触发 Timer.OnTimeUp，再让同一玩家于下一街行动，重放旧 Check/Call/Fold/AllIn 请求，断言行动玩家、奖池和版本不变；另覆盖重复请求和跨手请求。这是控制请求到达顺序的确定性测试，未模拟公网丢包。
