# 房间与牌桌

本项目是无限注德州扑克现金桌：玩家直接用账户筹码上桌，一手结束后自动续局。服务器是唯一权威，客户端只发送请求。

## 代码位置

| 部分 | 位置 |
| --- | --- |
| 房间、座位、会话 | `Assets/Scripts/Network/Rooms/`（`RoomManager`、`RoomInfo`、`PlayerManager`、`RoomDepartureService`、`TableParticipationService`） |

## 房间

- 登录后从大厅进入房间列表，可以建房或加入。一个账户同时只能关联一个房间。
- 房主可以在等待阶段设置：小盲（大盲 = 2 × 小盲）、思考时间、最大参战人数（2～16）、两手之间的等待秒数（1～60，默认 10）。
- 等待房间内，非房主准备后由房主开始。房主离开时自动移交；所有成员离开后房间立即删除。
- 房间号从 0 开始、只在服务器进程内有效，服务器重启后会重新使用。账户记录的“上次房间”只有在该账户仍是这个房间成员时才有效，否则在登录时清除。

## 参战与旁观

- 入座需要账户筹码至少一个大盲。筹码就是账户余额，没有单独的买入。
- 对局进行中加入房间的人先作为旁观者：没有座号、没有底牌、看不到他人私有信息。满桌也可以旁观；最大人数只限制参战名额。
- 旁观者可以申请“下一手参战”（需要名额和一个大盲），下一手开始前才分配座号并发牌；“继续旁观”取消申请。服务器会预留下一手名额，防止超额。
- 参战者可以预约“本手后旁观”或“本手后离开”。预约不影响本手的行动和奖池权益；弃牌或全下的玩家仍然属于本手，结算后才释放座位。
- 结算后筹码不足一个大盲的玩家转为旁观。
- 请求都带 `HandId` 和参战意图版本号，过期请求会被拒绝；身份一律来自已登录的连接。

## 座位与盲注

- 座号从 0 递增，离开后空出的座号不复用。
- 庄位和大小盲在本手合格玩家中按座号环绕推进，跳过空座；多人转为单挑时有专门处理。
- 下一手开始前，如果空座比例严格超过 50%，会按原顺序重新连续编号，并映射庄位和大盲位置，不改变相对顺序。进行中的手牌不压缩座号。

## 一手的流程

1. 开局时锁定每位参战者本手可用的筹码上限；本手中不能补充筹码。
2. 翻牌前、翻牌、转牌、河牌依次进行，最小加注、短码全下是否重新开放加注等按无限注规则处理。
3. 每个行动请求带 `HandId` 和 `TurnId`，已结束的行动机会、上一街、上一手或重复请求都会被拒绝。
4. 没有可行动的玩家时（如全员全下），服务器每 3 秒自动发一条街直到河牌。
5. 结算：按投入分层计算主池和边池，弃牌者的投入成为死钱，未被跟注的部分退还；平分时余数按庄位左侧顺序分配。全部参与者的净输赢在同一个事务中入账。

### 操作确认与提示

- 全下、跟注耗尽筹码、下注到全部可用筹码时，先显示剩余筹码并要求确认，默认焦点在“取消”。
- 当前可以免费过牌时点弃牌，会先确认；需要付出筹码的普通弃牌不额外确认。
- 确认框不暂停服务器计时。手牌、行动轮次或行动资格变化、牌桌关闭时自动关闭旧确认，旧回调不会提交到之后的轮次。
- 下注金额或房间参数被修正时，在输入框旁说明原因，不弹窗。
- 第一次进入旁观时说明“申请下一手、继续旁观、离开”和名额限制，之后不重复。
- 无法继续下一手时，服务器在同步消息中带上原因（`RoomTransitionReason`），参战者与旁观者分别看到返回等待房间或房间列表的说明。

### 超时与断线

- 思考超时：能过牌就自动过牌，否则自动弃牌。连续超时两次后，该玩家的思考时间缩短为 5 秒，主动操作一次后恢复。
- 本手中断线：座位保留；轮到时立即按上述规则自动操作，已全下的玩家仍参与奖池。
- 本手结束前重新登录：回到原座位继续，已自动完成的操作不撤销。
- 本手结束时仍未连接：转为旁观，但仍是房间成员，下次登录可以选择返回。
- 同一账户重新登录会替换旧连接；如果旧连接在房间中，新连接直接恢复房间状态。

## 结算后

- 结算后进入结果查看期，时长为房间设置的等待秒数。期间可以立即离开或转旁观；本手结束前发出的预约仍按预约处理。
- 结果面板列出未弃牌玩家的底牌、牌型和本手收益，公共牌置顶。未摊牌获胜时不公开底牌；对手全部弃牌后，获胜者可以在结果窗口主动亮牌（不可撤回）。
- 本手参战者可点“确认并准备”；所有需要确认的人都确认后跳过剩余等待。结果可在下一手中回看。
- 查看期结束后处理离开和旁观预约，重新统计合格人数：至少两人则自动开始下一手；不足两人则留在座位上的玩家回到等待房间，需要房主重新开始。

## 牌桌布局

牌桌按占座人数选择玩家名片的档位：1～4 人用 `Player4.prefab`（1 列，8:3），5～8 人用 `Player8.prefab`（2 列，4:3），9～16 人用 `Player16.prefab`（2 列，8:3），都在 `Assets/Prefabs/UI/Panels/GamePanel/`。每张名片的状态区在“思考倒计时”和“最近行动”之间切换，二者不会同时出现。字号、间距、弃牌透明度在对应 prefab 的 Inspector 中调整。

## 信息隐私

发给每位玩家的牌局数据由 `ClientGameInfo` 按座位裁剪：只含自己的底牌，旁观者没有底牌；不包含牌堆和其他玩家的私有信息。结算结果只复制已经公开的底牌。

## 存储故障

所有账户存储访问都经过 `GuardedAccountRepository`。出现意外的存储异常（初始化、读写、结算写入被拒绝等）时，服务器立即停止所有牌局，向所有连接尽力发送停服通知，500 毫秒后关闭网络服务；独立服务器以退出码 1 结束。客户端回到标题页并显示“服务器已停止服务”。正常的业务拒绝（密码错误、余额不足等）不会触发停服。

重启后，未结算的手牌会被标记为中止，不加减余额；已提交的结算保持不变。
