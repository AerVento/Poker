# 牌面

牌面决定玩家自己看到的扑克牌样式（手牌、公共牌、结算展示），只影响本地显示。新增或调整牌面的流程见 [poker-cosmetics](../../.agents/skills/poker-cosmetics/SKILL.md)。

| 预览图 | `Assets/Sprites/CardFaces/Previews/<预览名>.png`，384×256，包含黑桃 A 和牌背；经典预览留在本地，其余打进公共远程包 `previews/cardfaces` |
| 显示组件 `CardFaceView` | 脚本 `Assets/Scripts/UI/Shared/CardFaceView.cs`，prefab `Assets/Prefabs/UI/Shared/CardFaceView.prefab` |
| 当前装备 `CardFaceAppearance` | `Assets/Scripts/UI/Shared/CardFaceAppearance.cs` |

- 所有牌面共用同一个 `CardFaceView.prefab`，新增主题不需要新 prefab。组件提供 `SetCards(PokerCardsSO)` 与 `Display(Poker, bool showFront)`；装饰图关闭 Raycast Target，不含规则或网络组件。
- `PokerElement` 在远程牌面下载完成前使用经典牌面。

## 美术要求

52 张正面 + 1 张牌背，不含大小王；统一竖版 17:24，显示基准 204×288，原图建议至少 408×576。同一套的尺寸、透明边距和圆角位置一致，缩小到 102×144 时点数与花色仍清晰。导入为 Sprite（Single、Full Rect），带透明通道，不使用有损压缩；远程牌面的导入尺寸与压缩由 `Poker/Remote Artwork/Optimize Texture Imports` 统一设置。

每套牌面还必须同时制作一张 `Assets/Sprites/Items/CardFaces/cardface-<商品ID>.png`，经典、默认拥有和奖励专属款也适用。物品图标统一为三张扇形扑克牌，前一张显示主题的简化正面，后两张显示牌背；与商城小预览分别交付。具体风格、1024×1024 透明 PNG、导入、生成记录和小尺寸验收要求见 [UI 规范第 8.4 节](../Standards/UIConvention.md)。主题或牌背核心元素变化时同步更新图标。

## 商城与装备

- 商城与仓库的“牌面”页只显示小预览图，浏览与购买不下载整套牌面；预览包下载前预览位置为空。美术更新后执行 `Poker/Card Faces/Generate Previews`，从真实黑桃 A 与牌背重新生成预览，再执行 `Poker/Remote Artwork/Prepare Catalogs and Groups`。
- 未下载的预览上覆盖半透明黑色遮罩和下载图标按钮；点击后替换为进度条，成功后遮罩消失，失败后可再次点击重试。
- 未下载时可以购买，但已拥有款式的装备按钮为灰色“未下载”；下载完成后才允许装备。购买后不会自动装备；装备需要离开房间且没有进行中的手牌。
- 下载状态来自浏览器本地记录（见 [远程资源](../Operations/RemoteArtwork.md)），不等同于驻留内存；关闭界面或释放内存不影响已下载状态。已下载的旧版本仍算已下载，新版本在后台更新。
- 改名只改 `Items.json`，改价、上下架只改 `Shop.json`，然后重启服务器。`listed` 控制未拥有者是否可见，`purchasable` 控制购买；只有两者均为 `true` 时服务端接受购买。已售款式下架时设 `"listed": false`，保留条目与远程数据，拥有者仍可装备。
- 牌面与其他物品一样存在 `account_items`，显示在牌面页而不是道具页；可由服务器发放（见 [货币、商店与物品](Economy.md)）。装备记录保存物品 ID，空值表示经典款。
- 客户端缺少已装备款式的美术时显示经典，不修改服务器上的装备记录。
- 校验：`Poker/Card Faces/Validate Catalog`。代码：购买、装备走统一的物品请求（`NetworkRoom/NetworkRoom.Items.cs`、`Storage/SqliteAccountRepository.Items.cs`）。


## 幻想乡绘札

物品 ID 为 `cardface-gensokyo`。`Shop.json` 中 `"listed": true`、`"purchasable": false` 表示商城展示但禁止购买；`"price": 0` 不代表默认拥有。

在 `Configs/SlotMachine/Lottery.json` 的 `grand.rewards` 中添加下面的奖励条目；`weight` 是大奖池内的相对权重，按运营方案调整。保留其他奖励条目时会按权重共同抽取；只保留本条时，抽中大奖即获得此牌面。单次发放数量固定为 1。已拥有该牌面的玩家不会再抽中此条，概率由同池其他奖励分摊，见 [持有上限与已拥有奖励](SlotMachine.md#持有上限与已拥有奖励)。

```json
{
  "id": "gensokyo-deck",
  "weight": 1,
  "reward": [
    { "kind": "Item", "item-id": "cardface-gensokyo", "quantity": 1 }
  ]
}
```

部署时先在 WebGL 平台构建远程资源，上传所有 `.bundle`，再上传 `catalog_v1.*`，最后上传 `content-version.txt`；之后部署商城与奖池配置并重启服务端。新增此套美术沿用现有数据结构；是否需同时更新页面，以远程构建的内容格式检查为准。具体发布规则见[远程资源](../Operations/RemoteArtwork.md)。

- 图片：`Assets/Sprites/CardFaces/Gensokyo/`，53 张 816×1152 PNG，统一透明圆角。
- 数据：`Assets/RemoteContent/cardfaces/Gensokyo.asset`；远程地址 `cardfaces/gensokyo`，独立分组 `CardFace_gensokyo`。
- 预览：`Assets/Sprites/CardFaces/Previews/gensokyo.png`；公共预览集 `previews/cardfaces`。
- 原图和提示词：`ArtSources/CardFaces/Gensokyo/Deck/`、`DeckGeneration.json`、`Prompts.md`。

### 牌面设计

- 人物是视觉中心：Q 版人物与配套场景围绕牌面中央构图，可按动作适度偏移，不要求正中站立。帽子、翅膀、家具与局部背景计入整体构图，不能遮挡点数与花色。
- 暖白纸底、单层香槟金细边框、统一圆角。共用边框装饰仅保留顶部小阴阳玉与少量角落枝叶；角色专属装饰放在人物周围的局部留白中，不用大面积花枝、垂挂御札或两侧弹幕轨迹挤占人物空间。
- 左上显示大点数与标准花色图形，右下显示旋转 180 度的同组角标。数字与花色同色，不用颜色替代花色图形。
- 黑桃绿色 `#16834A`，梅花蓝色 `#246AC2`，方片橙色 `#D97816`，红桃红色 `#CC3648`。人物保留自身标志性色彩，不随花色统一染色。
- 正面不添加角色名称、说明、稀有度或其他标签。统一牌背不显示人物或点数信息，使用深靛蓝、金色阴阳纹与上下呼应的鸟居、樱花、御札纹饰。
- 正式输出统一为竖版 17:24，至少 408×576；透明边距、圆角、角标位置固定。按项目要求在 204×288 与 102×144 下检查人物辨识度及点数、花色清晰度。

### 整套人物画风

- 采用统一的简化日系 Q 版人物插画，保留脸型、神态、动作与服饰结构。以首张红桃 K 的人物表现为基础减少绘画细节；不采用方片 K 的圆头、豆豆眼与人偶式身体。头身比例可在约 2.5～3 头身范围试作，以角色表现和整套一致性为准，避免过度幼化。
- 脸部保留颊部与下巴轮廓、眼睑、虹膜和瞳孔、眉毛、小鼻与嘴形；眼睛可以有一个简洁高光，不堆叠复杂瞳孔渲染。每位角色独立设计脸型、眼形、眉形、视线与嘴形，不能只靠换衣服区分角色，也不默认所有角色都微笑。
- 统一的是线条、头身比例范围、上色方式与细节密度，不统一面部结构或表情。参考图只借用绘画技术与牌框，不继承上一位角色的眼神、头部倾斜、腮红或笑容；提示词不得把“复现面部结构”写进通用画风部分。
- 每张提示词分别明确脸型、眼形与瞳色、眉毛状态、视线目标、嘴部状态以及动作情境。瞳色按选用的人物设定版本确定，不设全套统一红瞳。不要让“自信、活泼、可爱”等宽泛形容词替代具体表情设计。
- 线条干净流畅，适度区分主轮廓与内部线条。平涂为主，每种材质只用少量大块阴影说明结构，减少多层渐变、密集发丝高光、布料反光与细碎明暗。
- 服饰保留领口、袖口、主要配饰、代表性图案和必要衣褶。减少褶皱数量与阴影层次，而不是删除衣服结构：例如裙子保留少数主要垂褶，肘部保留弯曲褶线，不完整描绘每一层细褶或蕾丝。头发保留发型与分束，不画成无结构色块。
- 动作不局限于站姿：坐地、坐椅、跪坐、倚靠、蹲下、飞行等均可按角色设定自由设计。保持一位主体人物，身体结构、重心、手势和与道具的接触关系清楚自然，不要求所有肢体都像站姿展示图一样露出；避免整套重复同一姿态。
- 花色配色与人物配色独立：花色颜色仅用于点数和花色图形，边框仍为香槟金；人物保持自身发色、服装色与自然肤色。不能按花色给人物统一染色，也不能添加对应色的光照、滤镜或描边。例如方片 K 的橙色不能改变八意永琳的银白头发和红蓝服装。
- 以 ZUN 原绘中的发色、服装、配饰与种族特征为人物识别基础；可从二创作品的表情、姿态和服装表现中获取灵感，不要求照抄原图，不复制整幅作品。不同来源统一转译到本套画风。
- 每张牌只有一位主体角色。允许围绕人物设计有情境的家具、道具与局部背景，例如扶手椅和茶桌、配药矮案或局部花田。人物尺寸按动作与场景适配，不把站姿高度比例机械套用到坐姿；保证脸部、表情和关键动作在小尺寸仍可辨认，场景不能挤小人物或侵入角标安全区。
- 后续人物制作沿用通过确认的样张作为风格参照，并排检查头身比例、脸型、五官、动作、线条、光影简化程度、服饰细节密度与整体占用面积。用户调整画风时同步更新本节，不能仅修改生成提示词。

### 人物设定与专属装饰

- 设计表情、动作和道具前，核对角色的性格、身份、能力与活动环境；从中选择适合本套 Q 版表现的神态与姿势，不给所有角色套用同一种笑容或卖萌动作。
- 以官方人物设定为基础，二创作品可提供视觉灵感，但不把未经核实的二创梗当成角色必备特征。保持独立原创构图和统一画风。
- 允许添加与角色有明确联系的小物、花草或小片环境，用于强化角色辨识度。例如风见幽香可配向日葵或局部向日葵花田，并保留从容、自信的神态与阳伞。
- 场景和装饰围绕一个清楚的行为或意象展开，可以安排在人物周围、身后或坐具下方，不局限于脚边的小物。家具允许符合透视的自然遮挡，但脸部、关键手势与角色服饰特征要可读，点数花色始终完整。
- 场景沿用人物的线条、简化光影和自然色彩，视觉权重低于人物，不受花色染色。允许窗景、墙面片段、花田、天空或地面等局部背景；以自然轮廓或淡出边缘衔接暖白留白，不覆盖整个牌面，也不另套生硬的矩形背景框。
- 画风统一不意味着构图统一。根据角色性格与活动自由发挥动作、家具和背景：例如蕾米莉亚坐在扶手椅上悠闲喝茶，旁边茶桌放茶具，仅是可选构图示例，不是该角色唯一允许的姿势。
- 整套检查既看画风一致，也看每位角色的表情、动作、服饰与装饰是否符合自身设定。
