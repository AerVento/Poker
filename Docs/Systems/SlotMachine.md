# 筹码抽奖界面

## 入口与状态

商城页签旁的“筹码抽奖”是入口按钮，通过 `UIManager.PushPanel<SlotMachinePanel>()` 打开独立页面。收藏模式不显示该入口。抽奖页面使用专属背景，左上角统一返回图标 Pop 当前页面，回到原来的商城页签与状态。

抽奖由服务端结算，每次消耗配置的美金，未中奖也会扣费。老虎机下方集中放置“抽 1 次”和“10 连抽”按钮，各自显示美金总价；拉杆仍执行单抽。顶部通过通用余额组件显示美金和筹码。美金不足时通过 `CurrencySystem` 自动兑换可用筹码补足差额；余额仍不足或牌局规则禁止兑换时不可抽取。右侧概率栏在未中奖概率下方显示保底进度，如“3 抽内必中奖”“下一抽必中奖”（见“保底”）。

服务端先按权重决定未中奖、小奖、中等奖或大奖；中奖后再按该档奖池的独立权重抽取一份奖励，玩家已拥有而会超出持有上限的奖励不参与抽取（见“持有上限与已拥有奖励”）。客户端只播放服务器返回的档位，不决定奖励。转轮停稳、拉杆复位后，单抽和十连抽均先展示“本次获得”：本次各抽实际获得的同类奖励合并显示，使用通用物品框，超宽时横向滚动；没有奖励时显示未中奖或持有上限状态。玩家可以确认结束，也可以打开“抽奖详情”。详情返回汇总，不确认回执；在汇总中确认或关闭才结束结果展示。

10 连抽按单次价格乘 10 收费，无折扣或保底；每次都独立按相同配置抽取。服务器先检查并支付整批费用，再在同一事务内执行 10 次抽取与发奖，不能用本批尚未获得的奖励补足入场费用。客户端播放一次转轮动画，展示本批最高中奖档位并按该档庆祝；抽奖详情按第 1 至第 10 抽的顺序单列展示，每行对应一次抽奖。行内逐项展示该次礼包的物品图标与数量，固定单行，超宽时横向滑动；整份结果纵向滚动，底部返回汇总按钮固定可见。不同抽次的重复奖品在详情中不合并，未中奖保留紧凑的一行；各档使用对应图标、标题与不同边框颜色区分。滚轮在详情物品区控制外层记录上下滚动，横向拖动或横向滚动条查看行内物品；纵向拖动传递给外层列表。全部未中奖时仍可查看完整 10 个结果。

## 表现

- 小奖使用红金筹码，中等奖使用冰蓝宝石，大奖使用紫红金冠。
- 单条中央中奖线，三个相同图案表示对应档位；未中奖从 24 种非三连组合中等概率随机选择，允许两个相同图案，不出现三个相同图案；仅影响停轮表现，不改变服务端中奖概率。
- 点击拉杆后约 0.24 秒朝玩家向下拉动：球头沿竖直方向移动并略微放大，杆身按透视缩短后向下伸展，底座固定。三个转轮连续纵向滚动，分别在 3.0、3.6、4.2 秒停稳，最后 0.45 秒减速；图案锁定与停轮音效在同一帧触发。结果出现时立即开始回弹，约 0.24 秒复位。
- 旋转期间拉杆禁用；中奖高亮对应档位并按下表播放庆祝表现。结果展示结束后可再抽，开始新一轮会清除上一轮特效与声音，滚动音乐请求会取代上一轮庆祝音乐及其自动恢复计划；未中奖播放失败音效，并在汇总中显示本次未中奖。
- 返回、关闭抽奖页或断线销毁页面时取消动画、停止该页面音效并释放专属背景音乐；重新进入先核对服务端保存的结果，有未展示结果时重新播放并展示奖励。
- 进入页面时，`GameAudioManager` 的单一音乐源切换至 132 BPM、16 小节的专属循环背景音乐。开始滚动时将页面音乐淡出并改播滚动专属短曲；最后一个转轮锁定且中奖时，切换到该档位的独占庆祝音乐，整首播放完成后再恢复抽奖页 BGM；未中奖独占播放失败旋律，播完后再过渡回页面音乐。离开页面后恢复原场景音乐。每次过渡为旧曲约 0.2 秒淡出、新曲约 0.4 秒淡入，停轮、拉杆与礼炮音效按原时机触发。页面 BGM、滚动音乐、三档中奖音乐和失败旋律由 `GameAudioManager` 统一互斥调度，遵循音乐音量和静音设置；拉杆、停轮与礼炮遵循音效设置。
- 停轮声提高约 5 dB；短音效预加载并以 PCM 导入。礼炮声与三轮发射分别同步触发，音乐静音不影响独立的音效设置。

| 档位 | 庆祝表现 | 持续时间 |
| --- | --- | --- |
| 小奖 | 中央一簇 18 片金色彩纸、轻微文字弹动、暖金灯光 | 约 2 秒 |
| 中等奖 | 两侧一次喷出 70 片蓝金彩纸与 6 条飘带、蓝金跑马灯、对应奖项呼吸高亮 | 约 3.8 秒 |
| 大奖 | 两侧金色礼炮连续发射三轮，共 252 片彩纸与 36 条飘带；炮口光晕、后坐动作、独立发射音效、柔和金色放射光及更明显的结果强调 | 约 7 秒 |

庆祝使用一个 uGUI 网格绘制彩纸、飘带和柔光，礼炮模块保存在 prefab。特效不拦截输入，限定在舞台区域，无全屏强闪烁；页面关闭时清除特效、停止声音。

## 奖池配置

入口：[`Configs/SlotMachine/Lottery.json`](../../Configs/SlotMachine/Lottery.json)。服务器启动时读取并校验，修改后重启服务器。`Poker/Slot Machine/Validate Configuration` 可在 Editor 校验，构建前也会自动校验。Windows 与 Linux 构建复制该文件；已存在的部署配置不会被覆盖。WebGL 不携带配置文件，价格与公示概率由服务端下发。

| 字段 | 含义 |
| --- | --- |
| `enabled` | 是否开放新抽奖；关闭后仍可查询已有结果 |
| `cost-dollars` | 单次美金费用，必须大于 0 |
| `none-weight` | 未中奖权重 |
| `pity-draws` | 保底抽数：连续 `pity-draws - 1` 抽未中奖后，下一抽必中小奖及以上；0 关闭保底，否则为 2～100 |
| `small`、`medium`、`grand` 的 `weight` | 三档中奖权重，与 `none-weight` 一起归一化 |
| 各档 `rewards` | 该档独立奖池；一次抽中其中一份奖励，每份 `reward` 是奖励条目数组（最多 8 条） |
| 奖品 `weight` | 档内权重，为正整数；奖励无需配置 ID，相同奖励可以放入多个奖池 |
| `reward[].kind` | `Dollars`（美金）、`Chips`（筹码）、`Item`（物品） |
| `reward[].quantity` | 数量，正整数 |
| `reward[].item-id` | 仅物品填写，引用 `Configs/Items/Items.json` 中的物品 ID（名片、牌面如 `namecard-galaxy`、`cardface-gensokyo`） |

当前的价格、保底、各档权重与奖品以 `Lottery.json` 为准，文档不复制具体数值。调整奖池时遵循以下原则：

- 用档位权重控制中奖频率，用档内权重和数量控制单次奖励大小；提高中奖率时相应降低单次奖励，保持整体回报率。
- 回报率按“平均返还价值 ÷ 单次费用”估算：美金按面值，商城物品按商城价打折（玩家通常不按原价看待礼物），不出售的限定外观作为追求目标不计入。美金返还比例决定抽奖回收货币的力度。
- 基础回报（美金与消耗品）承担大部分回报率；可购买的外观只占很低的权重，作为额外惊喜，避免玩家集齐外观后回报骤降。已拥有的外观会被排除（见“持有上限与已拥有奖励”）。
- 各档美金分多种额度，高额度权重较低，增加刺激感；同档放入多种物品与礼包，保持奖励多样。
- 大奖档的限定外观是最稀有的追求目标，中奖档的限定外观应比它更容易获得，否则档次颠倒。
- 不在 `Shop.json` 中的物品只能从奖励获得，适合作为抽奖限定奖品；商城中 `"purchasable": false` 的物品同样买不到，但会在商城展示。
- 改动后用“概率计算”复核每件关键奖品的单次概率与平均抽数，并考虑保底：中奖率越高，保底触发越少。

概率计算：某档权重 ÷ 四种结果权重总和；某奖励的总概率再乘以其档内权重 ÷ 该池奖励权重总和。权重不必凑成 100。关闭某档可将其档位权重设为 0；活动档必须有奖品。不存在的物品、无效数量、空奖池、重复字段及拼写错误会拒绝加载。

## 概率公示与奖池浏览

三档奖励卡显示对应的单次中奖概率，点击卡片打开 `SlotPrizePoolPanel`；页面同时公示未中奖概率。弹窗通过通用物品框展示图标与数量，点击图标查看名称和描述。每项列出“奖池内”概率及“单次抽中”概率，后者为档位概率乘以奖池内概率。例如小奖 30%、池内 60% 时，单次抽中为 18%。

概率数据由服务端按配置权重和该玩家的当前库存计算，与实际抽取使用同一规则，不在客户端另设数值。已拥有的奖励仍在奖池中列出，整行调暗并显示“已拥有”，单次抽中为 0%；其余奖励的池内概率按剩余权重重新计算。某档全部奖励都已拥有时，该档概率并入未中奖。`SlotLotteryAction.Pool` 是只读查询，不扣费、不抽奖，也不确认待展示奖励。每页最多 6 项，分页分母始终使用整个奖池的权重总和。`SlotLotteryDisclosure` 同时提供全部档位权重、所选池总权重、奖励总数和当前页内容，避免大池超出传输消息长度。零权重档仍可浏览，但中奖概率为 0%。

## 持有上限与已拥有奖励

每一抽先按配置权重决定档位，然后读取玩家当前库存：一份奖励中只要有任一物品发放后会超过 `Items.json` 的 `max-quantity`（名片、牌面为 1），这份奖励就不参与本次抽取，档内其余奖励按原权重重新归一化。档位概率不变；该档没有可抽奖励时本次记为未中奖。10 连抽每一抽都重新读取库存，前面抽中的外观不会在后面的抽次再次出现。消耗品上限极高，实际只有名片和牌面会被排除；统一奖励发放仍保留按剩余容量截断的兜底。

实现：`SlotLotteryCatalog.Fits`、`EligibleWeight` 与带筛选的 `SelectReward`；`SlotLotteryDisclosure.From` 用同一筛选生成玩家专属公示，已拥有的奖励以权重 0 下发。

## 保底

服务端按账号记录连续未中奖次数，单抽与 10 连抽共用并跨批次累计，在抽奖事务内与扣费、发奖一起提交（SQLite schema 17 的 `slot_pity`）。连续 `pity-draws - 1` 抽未中奖后，下一抽跳过未中奖，按小、中、大三档的配置权重抽取档位，跳过没有可抽奖励的档；随后照常按档内权重抽取奖励。任一抽中奖即清零；因已拥有而记为未中奖的抽次也计入未中奖。

`SlotLotteryDisclosure.PityDraws`、`PityMisses` 与 `DrawsUntilGuaranteed` 随每次响应下发玩家当前进度。客户端在结果展示完成并确认后才刷新保底进度，避免转轮停稳前泄露结果。各档公示概率为普通抽次的概率，不含保底触发时的变化。

实现：`SlotLotteryCatalog.IsGuaranteed`、`WinningWeight`、`SelectWinningTier`；计数读写在 `SqliteAccountRepository.SlotMachine.cs`。

## 扣费、发奖与结果恢复

`SlotLotteryRequest/Response` 通过已认证连接确认玩家身份。服务端使用安全随机整数完成两次抽取，价格与配置版本均由服务端核对。客户端发送操作 ID，不能指定抽奖结果；奖池浏览请求中的档位只用于选择公示内容。

SQLite schema 14 增加 `slot_draw_receipts`。兑换差额、扣费、奖励入账、流水、成就事实事件和结果回执在同一事务提交。货币溢出或未知物品仍撤销整笔操作；10 连抽中途出现此类失败会撤销整批。奖励结构和入账共用 [统一奖励](Economy.md#统一奖励)。

成功操作永久按账号及操作 ID 去重，同一操作 ID 不允许改成不同抽取次数。单次或整批结果均存入原回执表的 JSON，保留每次的档位与奖励，兼容既有单抽回执。页面未确认的结果保留为待展示状态；断线、丢失响应、离开页面或服务器重启都不会重复扣费发奖。重新进入先读取待展示结果，完成结果展示后发送确认。请求超时沿用原操作 ID 重试。奖池修改后旧回执仍有效，新抽奖必须使用最新价格版本。

主要实现：`Game/Economy/SlotLottery.cs`、`Network/Config/SlotLotteryConfiguration.cs`、`Network/NetworkRoom/NetworkRoom.SlotMachine.cs`、`Network/Accounts/Storage/SqliteAccountRepository.SlotMachine.cs`。

## 通用奖励展示

`RewardItemView` 预制体默认只显示图标和数量；点击图标，在旁边打开显示名称与说明的 Tooltip，点击外部关闭，不设关闭按钮。说明框根据文字量自动调整高度，超长正文滚动查看。美金、筹码使用统一货币图标，数量显示 `$80`；物品保持 `×10`；物品与外观沿用商城目录和远程美术资源。

`RewardPopupPanel` 通过 `UIManager` 注册和管理，接受多个奖励条目，奖励较多时滚动展示，支持关闭图标和 Esc。每日任务、成就单次领取及批量领取共用这个弹窗与物品组件。单抽和十连抽使用 `SlotBatchResultPanel` 展示合并汇总及逐抽详情，奖励格复用同一个 `RewardItemView`。弹窗只展示已入账奖励，不负责发放。

预制体：`Assets/Prefabs/UI/Shared/RewardItemView.prefab`、`RewardTooltipView.prefab`、`Assets/Prefabs/UI/Panels/RewardPopupPanel/RewardPopupPanel.prefab`。

组合奖品在奖池中显示条目数量和“项奖励”，点击查看完整内容；抽奖汇总和详情均直接逐项展示物品图标与数量。
