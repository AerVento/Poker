# 成就客户端缓存

## 刷新约定

目录和玩家状态分开传输、分开缓存。缓存由持久化的 NetworkRoom 持有，不属于 AchievementPanel，不写本地磁盘。共享目录中的隐藏定义始终是遮蔽版；真实隐藏定义只存在当前账号的完成状态中，切换账号时随状态一起清空，因此不会把一个账号已解锁的名称或奖励带给另一个账号。

| 时机 | 目录 | 玩家状态 |
| --- | --- | --- |
| 登录成功／重新登录 | 不预加载；已有同服务器目录保留 | 自动获取一次完整状态快照 |
| 首次打开面板 | 尚无目录时分页获取并缓存 | 登录快照可用且未过期则直接使用 |
| 关闭、再次打开 | 复用 | 无变化则复用；有进度变化或未加载成功则请求 |
| 普通进度变化 | 不请求 | 仅收 Changed=true，标记过期；下次打开或手动刷新时请求 |
| 收到 AchievementUnlocked | 不请求 | 先合入该项达成信息，再立即刷新状态，即使面板未打开 |
| 领奖成功／已领取回包 | 不请求 | 合入该项服务器状态，不重新下载目录 |
| 手动刷新 | 已有有效目录则复用 | 强制刷新状态；失败的目录加载也可重试 |
| 断线／换账号 | 同服务器目录保留 | 清空当前账号快照与未完成请求，重新登录再获取 |
| 切换服务器／重启客户端 | 切换服务器清除旧目录；进程退出后内存释放 | 重新获取 |

普通进度通知到来时，即使面板已经打开，也只标记并显示“进度有更新。”，不会立即拉取；再次打开或点击已有刷新按钮才更新。解锁通知则是立即刷新的例外。多个同帧解锁合并为一次状态刷新，不并发下载相同快照。

目录的 Revision 是完整定义内容的 SHA-256，包括隐藏定义的真实名称、描述、类别、图标路径、目标及奖励。普通目录项传完整定义；隐藏目录项只传统一遮蔽内容和 `Hidden=true`。玩家状态响应附带这个版本，隐藏成就完成后再随该项状态附带真实定义。重新登录后若同一服务器更新了目录，旧目录作废，在需要展示时重新下载，避免永久遗漏新增成就。

## 协议与职责

- `AchievementCatalogRequest/Response`：只传 `AchievementDefinitionView`，含 ID、名称、描述、类别、图标路径、目标、隐藏标记与默认奖励。隐藏项保留 ID、类别和标记，其余字段使用统一遮蔽值。
- `AchievementStatesRequest/Response`：只传 `AchievementStateView`，含 ID、进度、完成／领取时间及已解锁奖励快照；完成的隐藏项同时带真实 `RevealedDefinition`，未解锁项不传真实进度或定义。
- `AchievementProgressChanged`：业务载荷只有一个 bool 字段 `Changed`，发送到认证连接。账号隔离由当前连接与客户端登录会话负责，不携带列表。
- `AchievementUnlocked`：沿用已有横幅信息；客户端更新缓存不依赖 UIManager 或成就面板存在。
- `AchievementClaimResponse`：增加 `HasState`、`Revision`、`State`，成功或 AlreadyClaimed 时带回服务器状态。奖励发放与权限仍由服务器校验。
- `AchievementBatchClaimRequest/Response`：请求携带精确类别，空类别表示全部；响应返回本次领取数量、汇总美金／物品及所有更新后的状态。服务端从目录和玩家完成状态重新筛选，不信任客户端提供的成就 ID。
- 原 `AchievementsRequest/Response` 和 `AchievementService.GetStatus` 保留给既有诊断入口，正式面板不再用它下载混合列表。

新消息由 Mirror Weaver 按公开字段生成读写器；`Serialization.cs` 的现有自定义序列化只处理房间数据，不应把成就数据放入该 JSON 路径。协议有变动，服务端与客户端必须使用匹配版本；本次不改数据库 schema，也不改变成就 ID、判定或持久化奖励。

主要代码：

- `Assets/Scripts/Network/Achievements/AchievementClientCache.cs`：账号状态、目录合并、过期标记及完成／领取保留。
- `Assets/Scripts/Network/NetworkRoom.AchievementCache.cs`：登录预取、分页、超时、队列和网络响应生命周期。
- `Assets/Scripts/Network/NetworkRoom.Achievements.cs`：服务端通知与消息处理。
- `Assets/Scripts/Network/Achievements/AchievementService.cs`：独立投影及事务提交后的进度变化事件。
- `Assets/Scripts/UI/AchievementPanel/AchievementPanel.cs`：订阅缓存，展示与操作；关闭时只销毁视图，不取消网络层已经开始的加载。

## 服务端通知

AchievementService 处理业务事实，只有可见进度 Count 变化时才在事务成功提交后触发 ProgressChanged。只有内部 progress.Data 变化、重复消费或完成后的无关事件不会刷新 UI。完成仍沿用既有解锁通知。

NetworkRoom 收集变化账号，在现有通知周期中合并发送。该周期已经发了解锁通知就无需额外布尔通知；普通进度只发送一次 true，直到该连接开始下一轮状态请求，才允许再次发送。这不会替代正常成就进度保存或解锁检测，也不增加每帧查询数据库判断进度是否变化的轮询。

## 请求与竞态

- 目录与状态分别分页，每页最多 32 项，统一限制客户端请求节奏，避免触发现有速率限制。
- 分页完成后原子替换缓存，不向 UI 发布半份列表；校验页偏移、总数、下一页、版本及重复 ID。状态分页中 Revision 改变则从第一页重取。
- 超时或版本变化最多重启两次；仍失败则保留已有快照及过期标记，显示简短错误，等待下次打开或手动刷新，不无限轮询。
- 布尔通知、解锁、领奖会推进客户端 ChangeVersion；首个状态请求记录当时的值。若请求期间收到新变化，旧响应不能把 dirty 清掉。
- 解锁发生在请求中时，旧快照不能把该成就变回未完成；领奖回包推进状态 Revision，旧版本列表不会覆盖领取结果。必要时补取最新快照。
- 断线时丢弃分页工作，请求 ID 跨重新登录保持递增，并检查响应账号，防止旧请求污染新账号。目录按配置的服务器 URI 区分，关闭面板和重新登录不清除同服务器目录。
- 单项和批量领奖在账户已认证后均可使用，不因玩家处于房间或正在进行一手牌而禁用。奖励进入美金余额，不改变本手可下注筹码；请求仍受服务端账户事务、余额上限、物品上限和幂等校验。

## 展示排序与批量领取

客户端合并目录和状态后才决定显示。隐藏未完成项固定显示「隐藏成就」「继续游戏以解锁」、`Hidden-v1`、`?? / ??` 和 `??`，但保留真实类别参与页签统计。列表按已完成未领取、已完成已领取、普通未完成、隐藏未完成稳定排序，同组沿用目录顺序。

「一键领取」使用当前页签类别，覆盖该类别的所有可领取项而非当前滚动区域；「全部」发送空类别。服务端在单个成就账户事务中合并所有奖励，只调用一次 `Grant`，成功后统一写入领取时间和一次 Revision；任何发放校验失败时不标记其中任何一项。重复请求返回已领取且不再次入账。

## 验证范围

本次沿用用户要求，不运行自动化测试、人工合成事件测试、联机或 UI 操作测试，也不构建。执行 Unity 编译、协议／脚本元数据检查和代码审查；未验证真实登录、通知时序、重连、分页交错及界面交互，不以编译成功代替这些验证。
